# Пойдём?

Telegram Mini App для знакомств через совместные планы: сначала выбрать, что делать вместе, затем — с кем. MVP для дипломной работы и проверки гипотез на реальных пользователях.

## Текущий результат

По заданию пользователя для этапа 2 создан интерактивный демонстрационный frontend на React + TypeScript + Vite. Девять экранов: приветствие, анкета, главная, каталог, карточка человека, создание плана, мои планы, вдохновение и взаимный демомэтч.

Backend, Telegram-авторизация, база данных, бот и настоящие мэтчи не создавались. Данные статические. По последнему уточнению пользователя интерфейс не содержит служебных пометок о версии. Введённая анкета, фото и планы сохраняются в localStorage этого браузера. Реальной публикации, отправки приглашений и общения нет.

17.11.2026 frontend подготовлен к ручной публикации на Cloudflare Pages: `frontend/.node-version`, `frontend/wrangler.toml` и инструкция [DEPLOYMENT](docs/DEPLOYMENT.md). Утверждённая палитра централизована в `frontend/src/theme.css`: `#550707`, `#0599F6`, `#B8E4FF`. Макеты, типографика и фотографии сохранены. Публикация не выполнялась.

## Локальный запуск

Рекомендуется Node.js 22.13+ и npm. Из корня репозитория:

```powershell
cd frontend
npm ci
npm run dev
```

Точный адрес: **http://127.0.0.1:5173/**. Главная без анкеты: **http://127.0.0.1:5173/home**. Порт фиксирован: если 5173 занят, Vite сообщит об ошибке, а не выберет другой адрес. Переменные окружения и токен бота не нужны.

```powershell
npm run typecheck
npm run lint
npm run build
npm run test:e2e
npm run test:production
```

Браузерные проверки используют установленный Google Chrome в headless-режиме. Playwright сам запустит сервер. `test:production` проверяет содержимое `dist` после `npm run build`, включая прямые ссылки, работу без SDK и палитру. Production-просмотр: `npm run preview`, адрес **http://127.0.0.1:4173/**.

## Источники и границы

Оба PDF прочитаны полностью: презентация — 9 страниц, функциональный сценарий — 7; просмотрены все изображения. Второй PDF не содержит текстового слоя и прочитан визуально. Исходные PDF не изменены. Фотографии извлечены из презентации; внешнего фотосервиса нет. Шрифты поставляются локально через npm.

Подтверждённые функции отделены от предложений в PRODUCT и DECISIONS. Допущения интерфейса не становятся правилами реального подбора и мэтчей. Геопуши, платежи, реклама и собственный чат не добавлены.

Telegram SDK загружается асинхронно: браузерный прототип работает при его недоступности. Адаптация включает размеры окна, безопасные отступы, цвета оболочки и нативную кнопку «Назад» с проверкой поддерживаемых версий. Данные Telegram не используются для подтверждения личности. Проверка внутри настоящего Telegram требует HTTPS-адреса и здесь не заявляется выполненной.

Серверные переменные в [.env.example](.env.example) предварительные и пустые; frontend их пока не использует. Секретов в клиентских `VITE_`-переменных быть не должно. Коммиты и публикация — только по отдельному разрешению.
