Нейтральные обсуждения разрешены; бордели/притоны, аварийные объекты, закрытые крыши и незаконное проникновение на стройки запрещены. Отдельные «стриптиз»/наркотики вне нейтрального контекста тоже отклоняются. Python в Pages build не требуется.
- Исходные PDF в references/ не изменяй. При обращении к ним учитывай изображения и указывай страницы; о непрочитанных частях сообщай прямо.
- Стек: React + TypeScript + Vite; Python + FastAPI; PostgreSQL; SQLAlchemy 2; Alembic; aiogram; pytest; Docker Compose. Без микросервисов и необоснованной инфраструктуры.
- Текущий этап 4 — реальные пользовательские планы. Ручная Telegram-авторизация на двух аккаунтах завершена успешно по подтверждению пользователя; журнал — docs/TELEGRAM_MANUAL_TEST.md. При откликах или мэтчах изменение/отмена блокируются; физическое удаление планов и полная механика откликов/мэтчей пока не реализуются. Демо не восстанавливать. Alembic использует отдельную migration-role, API — runtime без DDL. pytest работает только с отдельной локальной БД *_test; без SQLite и незаметного skip при недоступной PostgreSQL. Секреты генерируются локально в игнорируемом .env, не выводятся в логи.
- Демонстрационный режим удалён по последнему указанию пользователя. Только ApiProvider/useAppData и серверные анкеты/фото/сессии; никаких переключателей, заполнения примером, вымышленных публикаций/мэтчей и fallback при ошибке API. Синтетические данные допустимы только в автоматизированных тестах. Редакционные идеи — data/editorial.ts, справочники — data/catalogs.ts. Планы, черновики, каталог и квота подключены к серверу; локального fallback нет. Старые demo-флаги/симуляции удаляются без чтения; обычный legacy-профиль игнорируется и очищается только явной очисткой или удалением аккаунта.
