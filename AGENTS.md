# Постоянные инструкции

- Проект — дипломный MVP Telegram Mini App «Пойдём?». Пиши документацию и пользовательские тексты по-русски.
- Сначала читай README.md, docs/PRODUCT.md, docs/DECISIONS.md и текущий этап docs/ROADMAP.md.
- Отличай подтверждённые требования от предложений. Не подменяй открытые вопросы решениями и не расширяй MVP без согласования. Последние явные инструкции пользователя приоритетны.
- Исходные PDF в references/ не изменяй. При обращении к ним учитывай изображения и указывай страницы; о непрочитанных частях сообщай прямо.
- Стек: React + TypeScript + Vite; Python + FastAPI; PostgreSQL; SQLAlchemy 2; Alembic; aiogram; pytest; Docker Compose. Без микросервисов и необоснованной инфраструктуры.
- Текущий этап 3.5 — ручная проверка настоящей Telegram-авторизации на двух аккаунтах. Читай docs/TELEGRAM_MANUAL_TEST.md. Разрешён только временный Quick Tunnel к Vite 5173 → proxy /api → настоящий backend 8001. PostgreSQL loopback, 8002 не использовать. Ручные результаты не подменять автоматизированными; не переходить к планам/мэтчам до завершения. Токен — только Set-TelegramToken.ps1, raw cookie/initData не выводить.
- Этапы 3.2–3.4 разрешены и реализованы: backend/, PostgreSQL/Compose, SQLAlchemy/Alembic, health/ref API, настоящая проверка Telegram initData, cookie/CSRF, собственная анкета/фото/удаление. Читай docs/TELEGRAM_AUTH.md. Бизнес-API планов/мэтчей, бот и admin UI ещё не реализованы. Дизайн frontend сохраняй.
- Перед продолжением читай docs/BACKEND_ARCHITECTURE.md, API_CONTRACT.md, DATABASE_SCHEMA.md, SECURITY.md, BACKEND_IMPLEMENTATION.md и backend/README.md. Архитектурная основа утверждена, но B01–B14 не закрыты общей командой начать каркас. Реальные анкеты, фото, согласия и квоты не хранятся в localStorage; клиентский Telegram ID не доказывает вход. Не открывай пользовательские записи до настоящей авторизации/проверки владельца.
- Запускай backend через python -m poidem из его .venv: Uvicorn требует явную SelectorEventLoop factory для psycopg async в Windows. Alembic использует отдельную migration-role, API — runtime без DDL. pytest работает только с отдельной локальной БД *_test; без SQLite и незаметного skip при недоступной PostgreSQL. Секреты генерируются локально в игнорируемом .env, не выводятся в логи.
- Демонстрационный режим удалён по последнему указанию пользователя. Только ApiProvider/useAppData и серверные анкеты/фото/сессии; никаких переключателей, заполнения примером, вымышленных публикаций/мэтчей и fallback при ошибке API. Синтетические данные допустимы только в автоматизированных тестах. Редакционные идеи — data/editorial.ts, справочники — data/catalogs.ts. До API планов каталог пуст, черновики только в памяти. Старые demo-флаги/симуляции удаляются без чтения; обычный legacy-профиль игнорируется и очищается только явной очисткой или удалением аккаунта.
- Подтверждённая механика: опубликованный план → анкета его автора → «Пойдём?» → автор принимает/отклоняет отклик → мэтч только при принятии. Имитаций больше нет. До подключения соответствующего backend нет публикаций, откликов, контактов, мэтчей или уведомлений; прямые старые ссылки показывают пустое состояние.
- Используй оригинальные PNG из references/brand без изменений, фильтров и искажений; рабочие копии — frontend/public/brand. Главная — только приветственный блок, без подборок и придуманной миссии. Убирай завершающие точки в авторских текстах UI, сохраняя внутреннюю пунктуацию и пользовательский ввод. «Посмотреть компанию» переименовано в «Посмотреть пару» без изменения адреса/действия. Авторский вопросительный знак в PNG сохраняй. Проверяй браузерный режим и Telegram safe areas.
- Текущая палитра: фон #550707, все акценты/подписи/стрелки/декор #B8E4FF, основной светлый текст #FFFFFF. Насыщенный голубой не используется; старые требования о нём отменены. Круглые стрелки прозрачные с #B8E4FF контуром и стрелкой. Общие токены — frontend/src/theme.css; оригинальные PNG не перекрашивай.
- Типографика: Forum для основных заголовков, Nicoletta Script для рукописных акцентов, Manrope для форм/мелкого текста. Пользователь разрешил е вместо отсутствующей ё в рукописных надписях: «пойдем?». Обычные тексты, имя проекта и пользовательский ввод глобально не транслитерируй. Присланный TTF подключён без изменения; метаданные ограничивают коммерческое использование. PNG-логотип шрифтом не заменяй.
- Десктопные приветствие и анкета: от 681 px фото приветствия на весь экран, полный PNG слева сверху, текст/действия слева снизу; у анкеты крупная фотография слева и форма справа. Мобильную композицию/порядок элементов сохраняй. По отдельному уточнению Forum и Nicoletta должны иметь сопоставимый визуальный размер: компенсация метрик шрифта плюс совместное уменьшение заголовка до доступной ширины, без переполнения и разрыва «пойдем?».
- Для frontend одна сборка: npm run build → dist, Root directory frontend. Пустой VITE_API_BASE_URL в production отключает real API, dev использует локальный proxy на 8001. Pages /api требует отдельного проксирования. Реальный HTTPS-тест в Telegram отложен до настройки доступа пользователем. Проверки: typecheck/lint/build/test:production/test:devices; test:auth и pytest запускай последовательно на одной *_test БД. Не туннелировать синтетический test API 8002.
- Мэтч требует согласия обоих пользователей и содержит ровно двух участников. Контактные данные для перехода в Telegram доступны только участникам после мэтча; ограничения проверяются на сервере.
- Не помещай секреты, реальные анкеты, фотографии пользователей и сырые данные авторизации в Git или логи. В клиентских переменных VITE_ секретов быть не должно.
- Подтверждено: целый возраст 18+ без верхней продуктовой границы; удаление аккаунта «Пойдём?» удаляет анкету/фото/все сессии. Судьба будущих совместных планов/истории — открытый B13; до решения запрещено молча каскадировать чужие записи. Фотографии выдаются только владельцу, пока не согласован просмотр кандидатов. Telegram-вход не подтверждает личность/возраст. Приватный MEDIA_ROOT должен быть общим для процессов одной БД.
- Лимиты 15 разных откликнувшихся без автора/повторов и 3 создания в день, правила текста — только frontend/src/config/planRules.ts; затем авторитетный backend. Клиентские ограничения не являются защитой. Не решай без согласования освобождение места после отказа/отмены, серверный календарь, удаление/сброс и учёт черновиков.
- Двухэтапная модерация, жалобы и блокировки подтверждены для будущего MVP; смысл этапов не задан. Не придумывай этапы или фиктивную проверку Telegram: реальную подпись/срок initData и ID проверяет сервер. Вымышленные значения надёжности удалены, реальная формула не согласована; не штрафуй за обычные отклики, молчание в опросе и неподтверждённые жалобы. Открытые вопросы — Q19–Q23 в docs/DECISIONS.md.
