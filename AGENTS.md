# Постоянные инструкции

- Проект — дипломный MVP Telegram Mini App «Пойдём?». Пиши документацию и пользовательские тексты по-русски.
- Сначала читай README.md, docs/PRODUCT.md, docs/DECISIONS.md и текущий этап docs/ROADMAP.md.
- Отличай подтверждённые требования от предложений. Не подменяй открытые вопросы решениями и не расширяй MVP без согласования. Последние явные инструкции пользователя приоритетны.
- Исходные PDF в references/ не изменяй. При обращении к ним учитывай изображения и указывай страницы; о непрочитанных частях сообщай прямо.
- Стек: React + TypeScript + Vite; Python + FastAPI; aiogram; PostgreSQL. Без микросервисов и необоснованной инфраструктуры.
- Текущий этап 2 по последнему заданию — интерактивный демонстрационный frontend в frontend/. Разрешены React + TypeScript + Vite, зависимости и проверки. Backend, авторизацию, БД, бота и настоящие мэтчи пока не создавай.
- Тестовые анкеты/планы храни отдельно в frontend/src/data/demo.ts. Деморежим включается переключателем «Демонстрационный режим» в анкете, по умолчанию выключен; значение и данные сохраняются в отдельных localStorage-ключах. В обычном режиме без backend каталог пуст, планы — локальные черновики. Тестовые публикации/люди/мэтчи видимы только при включённом деморежиме и явно обозначены; не смешивай их с редакционным «Вдохновением» или обычными данными.
- Подтверждённая механика: опубликованный план → анкета его автора → «Пойдём?» → автор принимает/отклоняет отклик → мэтч только при принятии. В деморежиме ответ вымышленного автора имитируется отдельным явным действием, входящий отклик на свой план также показывается явно. Без backend настоящих публикаций, откликов, контактов или уведомлений нет.
- Используй оригинальные PNG из references/brand без изменений, фильтров и искажений; рабочие копии — frontend/public/brand. Главная — только приветственный блок, без подборок и придуманной миссии. Убирай завершающие точки в авторских текстах UI, сохраняя внутреннюю пунктуацию и пользовательский ввод. «Посмотреть компанию» переименовано в «Посмотреть пару» без изменения адреса/действия. Авторский вопросительный знак в PNG сохраняй. Проверяй браузерный режим и Telegram safe areas.
- Текущая палитра: фон #550707, все акценты/подписи/стрелки/декор #B8E4FF, основной светлый текст #FFFFFF. Насыщенный голубой не используется; старые требования о нём отменены. Круглые стрелки прозрачные с #B8E4FF контуром и стрелкой. Общие токены — frontend/src/theme.css; оригинальные PNG не перекрашивай.
- Типографика: Forum для основных заголовков, Nicoletta Script для рукописных акцентов, Manrope для форм/мелкого текста. Пользователь разрешил е вместо отсутствующей ё в рукописных надписях: «пойдем?». Обычные тексты, имя проекта и пользовательский ввод глобально не транслитерируй. Присланный TTF подключён без изменения; метаданные ограничивают коммерческое использование. PNG-логотип шрифтом не заменяй.
- Десктопные приветствие и анкета: от 681 px фото приветствия на весь экран, полный PNG слева сверху, текст/действия слева снизу; у анкеты крупная фотография слева и форма справа. Мобильную композицию/порядок элементов сохраняй. По отдельному уточнению Forum и Nicoletta должны иметь сопоставимый визуальный размер: компенсация метрик шрифта плюс совместное уменьшение заголовка до доступной ширины, без переполнения и разрыва «пойдем?».
- Для frontend сохраняется одна сборка: npm run build → dist, Root directory frontend для прежней конфигурации Pages. Проверки: npm run typecheck, npm run lint, npm run test:production; при доступном WebKit — npm run test:devices. Разделение demo/public и изменение регистрации не входят в последнее визуальное задание. Самостоятельно не публиковать.
- Мэтч требует согласия обоих пользователей и содержит ровно двух участников. Контактные данные для перехода в Telegram доступны только участникам после мэтча; ограничения проверяются на сервере.
- Не помещай секреты, реальные анкеты, фотографии пользователей и сырые данные авторизации в Git или логи. В клиентских переменных VITE_ секретов быть не должно.
- Лимиты 15 разных откликнувшихся без автора/повторов и 3 создания в день, правила текста — только frontend/src/config/planRules.ts; затем авторитетный backend. Клиентские ограничения не являются защитой. Не решай без согласования освобождение места после отказа/отмены, серверный календарь, удаление/сброс и учёт черновиков.
- Двухэтапная модерация, жалобы и блокировки подтверждены для будущего MVP; смысл этапов не задан. Не придумывай этапы или фиктивную проверку Telegram: реальную подпись/срок initData и ID проверяет сервер. Надёжность сейчас — отдельные явно вымышленные значения без формулы; не штрафуй за обычные отклики, молчание в опросе и неподтверждённые жалобы. Открытые вопросы — Q19–Q23 в docs/DECISIONS.md.
- Для каждого этапа предусматривай подходящие проверки. Сообщай, что реально запускалось, результат и ограничения; незапущенные тесты не называй успешными.
- Последнее задание ограничено тремя визуальными правками: физически отделить PNG-бокалы мэтча от текста до 430 px, заменить звёздочку на SVG и добавить отдельный размытый фотослой на /home. Деморежим, регистрацию, механику и остальные экраны не менять; прежнее приветствие / сохранить. Не вводить новые оттенки в существующий дизайн.
- Последнее уточнение: у заголовка «Твои маленькие большие планы» только до 375 px локально уменьшен line-height рукописного em до .65; размер/шрифт/цвет и широкие экраны сохраняй. Рядом с надёжностью не выводи «тестовые данные»; сами вымышленные значения остаются только в явно включённом деморежиме.
- Обновляй требования, решения и дорожную карту при согласованных изменениях. Не создавай коммиты и не публикуй код без отдельного разрешения.
