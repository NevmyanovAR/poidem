# Этап 11А — поиск общественных мест через 2ГИС (D64)

## Реализация и актуальный статус

Поставщик — один серверный 2ГИС Places API 3.0. Geoapify не используется как резервный источник. В локальном .env уже предоставлены DGIS_API_KEY и DGIS_STORAGE_APPROVED=true; в этом продолжении они использованы, ключ не выводился и не переносился в frontend/Git. Production-деплой не выполняется; в .env.example разрешение по-прежнему false. При отсутствии ключа/разрешения — 503, без выдуманных результатов.

Поле «Где встречаемся?» ищет после трёх символов и паузы 350 мс. Список показывает название, категорию и адрес, поддерживает клавиатуру, очистку, ошибки/повтор. Выбор вызывает серверный byid. Ключ — только backend, текст и координаты клиента не доказывают допустимость объекта.

## Политика и хранение

Allowlist: кафе/кофейни, рестораны, обычные бары, музеи/галереи/выставочные пространства, кинотеатры, театры, парки/скверы, культурные центры. При живой проверке добавлены точные рубрики 2ГИС «Художественные выставки» и «Точки кофе»: первая нужна, в частности, для Третьяковской галереи. Кофейные автоматы, интересные здания сами по себе, магазины/офисы и неизвестные категории не допускаются. Исключения частного/закрытого/жилого объекта, гостиницы/номера, запрещённой тематики имеют приоритет. Кафе внутри жилого дома — отдельный branch, не одобрение всего здания.

Результаты не гарантируют безопасность, доступность и часы работы. Ответ поставщика может содержать нечёткие совпадения: пользователь выбирает заведение по его фактическому имени и адресу. Не подменяем Cavita на Cavina и не объявляем такой результат точным совпадением.

Миграция 0011: прежний Plan получает минимальный venue-снимок/политику; одна таблица place_selections с привязкой к владельцу. Поля: provider/id/name/address/point/category/checked_at/policy_version. Серверный selection_id принадлежит конкретному пользователю. Нельзя прислать свою категорию, координаты или произвольный адрес вместо выбора. При публикации проверка повторяется после настроенного срока давности. Политика централизована в services/place_policy.py, адаптер в place_provider.py.

Старые планы сохраняют адреса и policy=NULL без ложной отметки проверки. Согласованные встречи, мэтчи, чаты и история не меняются. Черновик сохраняется без внешнего запроса; публикация нового плана с неподтверждённым местом не разрешается. Квота и прежние ограничения команд сохранены.

Кэш — память процесса, максимум 256 запросов, 60 секунд по умолчанию, настраивается в пределах 0–300. Запросы ограничены на пользователя; 2 параллельных запроса поставщику и пауза 250 мс. У запросов нет автоматических повторов. Исправлено чтение JSON-ответов до EOF с общим лимитом 256 KiB: один read(n) мог вернуть только часть ответа и приводить к ложному 503. Регрессии проверяют фрагменты по 7 байт и суммарный лимит тела. При местных сетевых задержках timeout в игнорируемом .env поднят до 10 секунд; 429/503 остаются честными ошибками с возможностью сохранить черновик. Не копируется каталог целиком. Разрешение хранения задаёт владелец ключа, код не устанавливает наличие лицензии сам.

## API и настройки

- GET /api/v1/places/search?q=... — только авторизованному активному пользователю
- POST /api/v1/places/resolve — {provider_place_id}, сессия/CSRF/Origin
- Прежние POST /plans, PATCH /plans/{id}, POST /plans/{id}/publish используют server-owned выбор

Получить ключ своего проекта и проверить включённые продукты/условия можно в [кабинете 2ГИС](https://platform.2gis.ru/). Безопасный ввод из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Set-PlacesKey.ps1 -Provider 2GIS
```

DGIS_STORAGE_APPROVED=true выставляется только владельцем после подтверждения условий своего договора/тарифа. Ключ не присылать в чат. После изменения .env перезапустить API. Дополнительные переменные PLACES_TIMEOUT_SECONDS/SEARCH_PER_MINUTE/RESOLVE_PER_MINUTE/CACHE_SECONDS/REVALIDATE_SECONDS и PLACES_BIAS_LONGITUDE/LATITUDE. Географическая точка — приоритет поиска, а не согласованная граница города запуска.

Официальные методы: [поиск объектов](https://docs.2gis.com/en/api/search/places/reference/3.0/items), [byid](https://docs.2gis.com/en/api/search/places/reference/3.0/items/byid), [обзор и учёт запросов](https://docs.2gis.com/en/api/search/places/overview). Успешный HTTP/ответ не заменяет ручную проверку соответствия названия и адреса. Актуальный тариф/лимит задаёт кабинет владельца ключа, неподтверждённую цену в код не закладываем.

## Проверка и ограничения

27.11.2026 проведён живой поиск 2ГИС и byid по Москве. Финальный прогон: 8 запросов поиска и 8 проверок byid завершились успешно; Cavita даёт только нечёткие альтернативы, не точное совпадение. Первый прогон выявил отсутствие рубрики художественных выставок: галерея возвращалась поставщиком, но фильтровалась приложением. Это исправлено; кофейни с рубрикой «Точки кофе» тоже распознаются. Точные публичные результаты и сетевые ошибки сохранены без ключа в .local/2gis-check-*.json. Cavita возвращает нечёткие совпадения, точное заведение не подтверждено.

Отдельный opt-in backend/tests/live_stage11_check.py прошёл полный HTTP/API-путь: реальная галерея в поиске → byid → выбор → создание/публикация → видимость второму аккаунту → ручное одобрение синтетического селфи → публичная отметка → её сброс при замене фото. Все пользователи/фото/планы этого теста находятся только в отдельной *_test БД, данные основного стенда не создавались и не сбрасывались. Это не ручной вход Telegram или тест физической камеры.

```powershell
docker compose --profile test up -d --wait db-test
$liveTemp = Join-Path '.local' ('pytest-live-stage11-' + [guid]::NewGuid().ToString('N'))
.\backend\.venv\Scripts\python.exe -m pytest -p no:cacheprovider --basetemp $liveTemp backend/tests/live_stage11_check.py -q
.\backend\.venv\Scripts\python.exe -X utf8 scripts/check_2gis_places.py
```

Не запускать opt-in и обычный pytest одновременно на одной *_test БД. Тест делает ограниченное число настоящих запросов по ключу; не входит в обычный сбор pytest. Ручная очередь отсутствующих мест остаётся отдельной небольшой задачей, как разрешено исходным заданием: нельзя одобрить произвольный адрес без подтверждения общественного объекта.

Актуальные результаты регрессий и локальной приёмки — в [общем отчёте](STAGE11_ACCEPTANCE.md). Никаких commit/push/production-деплоя.
