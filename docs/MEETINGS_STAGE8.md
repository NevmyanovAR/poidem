## Результат встречи

Источник — прежние Survey и FeedbackAnswer. Засчитывается только завершённый ответ
с met=true/false. Незавершённое Да без оценки, отсутствие строки и молчание — не Нет

| Завершённые ответы | API result | Представление |
|---|---|---|
| Да / Да | mutual_yes | Оба подтвердили встречу |
| Нет / Нет | mutual_no | По ответам обоих встреча не состоялась |
| Один ответ | insufficient | Ожидаем ответ второго участника / Остался твой ответ |
| Да / Нет | conflicting | Ответы не совпали |
| Нет завершённых ответов | no_data | Нет данных о встрече |

Это взаимный самоотчёт. Архивирование, дата плана, жалоба или блокировка
не подтверждают фактическую встречу, неявку и вину. Отмена отдельно запрещает
ответ, сохранённые ответы не удаляются. После срока результат остаётся читаемым

## Показатель и пересчёт

Версия **D58-mutual-unique-partners-v1**. Сервер считает COUNT(DISTINCT partner_id)
для пользователя по существующим Match → Survey → двум FeedbackAnswer:

- обе стороны завершили ответ и сообщили Да
- прежняя согласованная политика опроса, время открытия опроса наступило
- план не отменён

Архив не исключает подтверждения; жалоба, личный блок, скрытие плана модератором,
оценка, комментарий, обычный отклик и отказ не участвуют в расчёте.
Новый партнёр может увеличить счётчик на один, повтор той же пары — нет.
Исправление ответа сразу пересчитывает результат: если у этой пары не осталось
других взаимных Да, она больше не входит в счётчик. Это не штраф

Расчёт по источнику выбран вместо второго изменяемого счёта/журнала самоотчётов:
повторные запросы не накапливают события, исправление не оставляет устаревшую оценку,
перезапуск процесса не влияет на результат. Прежняя reliability_events сохраняется,
но этот этап не записывает в неё «доказанные» нарушения/неявки или назначенные баллы.
Её source_event_key/verification_state остаются основой для будущих утверждённых
событий администратора. Новые таблицы, materialized aggregates и worker не нужны

Публично выдаются только число и версия, через существующие защищённые контексты
анкеты плана/отклика/мэтча. Общего каталога пользователей и списка партнёров нет.
Смена имени/возраста/описания/фото не меняет постоянный серверный UUID и результат.
Новые копии старых фото не сохраняются. Отметка «Анкета обновлена» не добавляется:
любая правка не является событием безопасности, а отдельной политики снимков/сроков
хранения фото не утверждено. B13 не меняется

## API и безопасность

Все адреса ниже с префиксом `/api/v1`, прежние cookie, account context и CSRF

| Метод | Адрес | Данные/права |
|---|---|---|
| GET | /matches/{id}/survey | Только участник; общий результат, собственный ответ, доступность/срок |
| POST | /matches/{id}/feedback | Только собственная сторона, CSRF; тот же опрос/ответ, не второй канал оценок |
| GET | /me/reliability | Только собственный показатель |
| GET | существующие публичные анкеты | Дополнительное поле experience: число/версия |
| GET | /admin/reports/{id} | Дополнительный meeting_review только по разрешённой связанной жалобе |

Feedback input: `{met:boolean,rating:1..5|null,comment:string|null}`.
При Да оценка обязательна; при Нет rating/comment отсутствуют либо null.
Комментарий до 2000 символов, пробелы по краям убираются. Лишние поля, user_id,
participant_side, Telegram ID, score и policy_version отклоняются с 422.
401 без входа, 404 постороннему (включая admin, не участвующего во встрече),
403 без CSRF, 409 при недоступном окне ответа. Ошибка API не превращается в «нет данных»

DTO survey не включает чужую оценку/комментарий и Telegram-контакты.
Статусы available/upcoming/expired/cancelled/not_scheduled вычисляются для UI,
новые enum-статусы БД не создаются. Старым мэтчам без Survey опрос не назначается

Бот и HTTP сериализуют изменение одной строкой Survey, а PK(survey_id,side)
не допускает третьей стороны/дублирования ответа. Одинаковый окончательный ответ,
оценка или комментарий не меняют submitted_at/updated_at; прежняя дедупликация
Telegram update сохраняется. Исправление ответа остаётся доступным по B09

HTTP не требует доставки вопроса ботом: доступность определяется серверным временем,
политикой и сроком получателя, без обхода отмены/закрытия опроса. Opt-out управляет
уведомлениями, а не правом на собственный ответ. Ответ из Mini App подавит ненужную
последующую доставку вопроса согласно прежней проверке completion_state

Связь жалобы с мэтчем и минимальный результат на момент подачи сохраняются
сервером в прежнем evidence JSONB. Администратору дополнительно вычисляется текущий
результат. Перед выдачей проверяется соответствие reporter/reported двум участникам.
Для старых chat/match-жалоб допустим прежний серверный target_key; произвольная анкета
не привязывается к угадываемой встрече. Нет admin API свободного чтения опросов/чатов.
Решения остаются dismiss/hide_plan; confirm_violation/штрафы/баны не добавлены

**Миграций нет, head 0008**, прежние 33 таблицы. Секретов, новых переменных окружения
и зависимостей не добавлено

## Интерфейс

В подробностях мэтча/архивной встречи — компактные «Итоги встречи», собственный статус,
возможность ответить/исправить ответ в разрешённый срок. Выбор Да раскрывает оценку
и необязательный комментарий. Приложение говорит, что они не показываются партнёру.
После отправки форма сворачивается. Общий результат обновляется при возвращении
в приложение и периодически, пока экран открыт. В обычные MatchCard опрос не добавлен

В разрешённых анкетах и собственной анкете — «Взаимные подтверждения · N»
с доступным пояснением, что считаются уникальные партнёры. Это не «верификация»
и не публичные звёзды. В мэтче счётчик находится внутри «Анкеты партнёра» под именем,
чтобы его не принимали за оценку конкретной встречи. В /admin у связанной жалобы — результат, наличие ответов
и прежний результат при изменении после обращения, без приватных отзывов

Новая вкладка не добавлена. Исходные фотографии/PNG, шрифты, приветствие и навигация
сохранены; оформление использует прежние CSS-токены и компактные формы

## Ручная проверка A/B/C

Только временный стенд и тестовые аккаунты/данные. Полную ручную проверку этого этапа
ещё предстоит выполнить пользователю; предыдущий успешный этап не заменяет её

1. A и B входят через кнопку Mini App, C — существующий отдельно назначенный admin.
   Защищённое назначение роли: [SAFETY_STAGE7](SAFETY_STAGE7.md)
   Для ветки опроса в боте заранее отправить /start и включить уведомления inline-кнопкой.
   При выключенных уведомлениях ответ в Mini App всё равно доступен в разрешённый срок
2. A создаёт новый будущий план, B откликается, A принимает. Не сбрасывать квоты
3. До начала +2 часа новый блок опроса не появляется; прямой POST недоступен.
   Дождаться настоящего времени +2 часа. Не менять часы основной БД/компьютера и не
   запускать синтетический API ради обхода срока. Для быстрых матриц используются pytest
4. A отвечает Да с оценкой/комментарием через бота либо подробности мэтча.
   A видит «Ожидаем ответ второго участника», B — «Остался твой ответ».
   У B нет доступа к оценке и комментарию A
5. B отвечает Нет: у обоих «Ответы не совпали», счётчик не увеличивается.
   A вручную отправляет жалобу из шапки мэтча, C открывает именно её в /admin:
   виден результат, нет индивидуальных оценок/комментариев и новых санкций.
   Отдельные сообщения по D57 не имеют меню жалобы
6. До 7 дней B исправляет ответ на Да и завершает оценку. У обоих «Оба подтвердили
   встречу», счётчик увеличивается на одного партнёра. В жалобе C видит текущий результат
   и что при подаче было противоречие. Жалоба сама по себе ничего не уменьшает
7. Закрыть/открыть приложение и, при необходимости, перезапустить один существующий
   процесс бота/worker: ответы/счётчик сохраняются. Повторная операция не увеличивает число
8. Сменить имя/фото A: история не обнуляется. В плане A/анкете у B число прежнее.
   При повторной встрече той же пары число не увеличивается ещё раз
9. После 7 календарных дней архив и результат доступны, кнопок изменения нет.
   Молчание второго участника остаётся недостатком информации, а не неявкой
10. C как посторонний не может читать /matches/{id}/survey и отвечать за A/B.
    Личная блокировка не удаляет ответы/мэтч/чат и не уменьшает показатель.
    Настоящие сообщения/доставку/поведение iPhone проверять отдельно от mocked Bot API
