# Собственный каталог мест и компактная фотоверификация — D66

> Историческое описание: обязательность каталога/одобрения заменена D67 — [свободный ввод и репутация](FREE_PLACES_REPUTATION_STAGE11V.md). Данные и миграции сохранены

## Подтверждённое задание

Новое задание пользователя заменяет зависимость от 2ГИС собственным каталогом с ручной модерацией. Внешние Places API, ключи, платные запросы и автоматический импорт прежних данных не используются. Исторические миграции 0011/0012 и снимки мест не удаляются. Меняется только UI фотоверификации: backend, права, согласие/версия, хранение, проверка жеста и фотографии, уведомления остаются по D65.

## Устройство и миграция

0013 добавляет public_places: UUID, название/адрес/город/категория, dedupe_key/search_text, pending/approved/rejected/hidden, версия, автор предложения, даты и сотрудник решения, причина. Всего 38 таблиц. Прежний place_selections используется повторно для выбора из собственного каталога; provider=local, policy=local-catalog-v1. Координаты не выдумываются: latitude/longitude=null. У предложения pending checked_at=null; это не проверенное место. Удаление аккаунта снимает связь автора предложения через SET NULL, публичный каталог и исторические адреса не удаляет; прочие ограничения B13 сохранены.

Критические проверки выполняет FastAPI. Клиент не назначает одобрение, автора или категорию/координаты в снимке. Свой selection_id ссылается на серверный снимок. При публикации объект заново читается в PostgreSQL с FOR SHARE и должен быть approved; скрытие/редактирование берёт FOR UPDATE. Поэтому старый кэш/ID/статус не обходят проверку. Автор может сохранять pending-выбор в черновик; после одобрения серверные allowed_actions разрешают публикацию. Актуальные сведения отображаются в черновике, а сохраняются окончательным снимком при явной публикации. Уже опубликованные планы/мэтчи/чаты не переадресуются при редактировании/скрытии каталога.

Новые публикации старых черновиков с 2ГИС/произвольным адресом требуют выбора собственного одобренного места. Уже опубликованные старые планы сохраняют прежний адрес и возможность прежних разрешённых действий без подмены места. Никакого массового обновления старых адресов. Квота 3 плана/сутки и запрет изменения связанных планов прежние.

Точный дубликат определяется нормализованными названием+адресом+городом (NFKC, регистр/ё/пробелы/пунктуация), категория не позволяет обойти уникальность. UNIQUE + транзакционная блокировка ключа защищают параллельные предложения/редактирование/CSV. Повтор своего предложения возвращает ту же запись; одобренный объект может выбрать любой пользователь. Чужое неодобренное совпадение даёт понятный 409 без раскрытия владельца. Похожие названия/адреса показываются модератору, не объединяются автоматически. Подсказки похожести ограничены 100 кандидатами/10 совпадениями и могут не найти все варианты сокращений.

## Категории и работа модератора

Разрешены cafe, restaurant, bar, museum, gallery, cinema, theatre, park, culture. Неизвестная/частная категория не принимается. Прежний текстовый фильтр запрещённых тем проверяет название, адрес, город; нейтральные обсуждения и правила D47/D48 не меняются. Наличие адреса или пользовательский выбор категории не подтверждают общественную доступность — её проверяет человек.

В /admin → «Места» используется прежнее разрешение moderation: moderator/admin/owner; user/analyst получают 403. Доступ проверяется каждым запросом; изменения требуют CSRF/Origin/account context, expected_version, причину и аудит. Для одобрения и редактирования уже одобренного объекта нужно явно подтвердить проверку существования, адреса и публичного доступа. Исторические поля и чужие анкеты сотруднику этим разделом не открываются.

По умолчанию pending; есть поиск и фильтры approved/rejected/hidden. В деталях можно исправить поля, одобрить/отклонить с причиной, скрыть из будущих подсказок. Скрытый/отклонённый объект можно одобрить только новым явным проверенным решением. Изменения и чтения пишутся в прежний admin_audit_log. Два решения с одной версией не проходят одновременно. Причина отказа доступна автору в собственном черновике/предложении; публичные подсказки включают только approved.

## Наполнение CSV

1. Назначенный сотрудник открывает /admin → Места → «Наполнить каталог из CSV»
2. Скачивает шаблон /templates/places.csv; репозиторная копия docs/examples/places.csv содержит только заголовок, без придуманных реальных адресов
3. В UTF-8 CSV с запятой заполняет столбцы строго в порядке name,address,city,category. Адреса/названия с запятой заключает в двойные кавычки по правилам CSV
4. Проверяет реальное существование и публичный доступ каждого объекта, выбирает файл, подтверждает «Все объекты в CSV проверены мной», затем подтверждает импорт
5. Видит число добавленных/уже существующих. Точные существующие записи не перезаписываются, pending/rejected/hidden не одобряются импортом задним числом — их надо рассмотреть отдельно

Пример структуры (угловые скобки нужно заменить собственными проверенными данными; это не готовая строка наполнения):

```csv
name,address,city,category
<Название проверенного объекта>,<Проверенный адрес>,<Город>,museum
```

Ограничения: 1–100 строк, файл до 64 КиБ. Неизвестные заголовки/категории, повтор внутри файла, неправильные поля и запрещённый текст отклоняются до записи всего пакета. Нет частичного наполнения при ошибке валидации. CSV добавляет только реально проверенные оператором объекты, не объявляет автопроверку. Карту/фото заведений не добавляем.

## API

| Метод | Путь /api/v1 | Доступ |
|---|---|---|
| GET | /places/search?q=... | Авторизованный active, только approved |
| POST | /places/resolve | Авторизованный active + CSRF; approved или своё предложение |
| POST | /places/proposals | name/address/city/category; автор из сессии |
| GET | /me/place-proposals | Свои статусы/причины, серверная пагинация |
| GET | /admin/places | moderation, q/state/offset/limit |
| GET | /admin/places/{id} | moderation, подробности/возможные совпадения/аудит |
| PUT | /admin/places/{id} | moderation + CSRF/версия/причина |
| POST | /admin/places/{id}/decision | approve/reject/hide, версия/причина/подтверждение |
| POST | /admin/places/import | CSV + явное подтверждение предварительной проверки |

Сохраняются прежние POST/PATCH/публикация планов. Поиск после 3 символов, debounce 350 мс, управление клавиатурой, ошибки/очистка; пустой каталог предлагает новое место и не выдаётся за ошибку сервиса. Лимиты поиска/выбора/предложения прежними PLACES_SEARCH_PER_MINUTE/PLACES_RESOLVE_PER_MINUTE. Сервер не совершает сетевых запросов. Неиспользуемые DGIS/GEOAPIFY настройки в старом .env игнорируются; значения секретов не печатаются и не переносятся. Образец окружения и Compose больше их не требуют. Старый сетевой адаптер и диагностические скрипты удалены вместе с устаревшими сетевыми тестами; заменены тестами каталога/модерации/дубликатов/CSV/публикации без сети.

## Компактная фотоверификация

Основной экран: заголовок → одно короткое объяснение → небольшая иллюстрация → обязательный чекбокс со ссылкой «Условия согласия» → камера. Полный текст согласия, реальные сроки, хорошее освещение и ограничения метода доступны в прежнем Modal до согласия, не дублируются на странице. Версия согласия по-прежнему проверяется сервером; смена версии снимает локальный checkbox.

Во время камеры: серверный жест, video с прежними playsInline/muted/facingMode, большая основная кнопка и отдельная вторичная «Закрыть камеру». Действия стоят вертикально с gap 12px, высота не меньше 48px, текст может переноситься. Элементы не позиционируются друг поверх друга. После съёмки — просмотр, отправка, пересъёмка и выход. Статусы и отзыв согласия сохранены. Видео/Blob cleanup и обработка разрешений не меняются; пауза существующего foreground refresh на открытых условиях не даёт перестраивать чтение модального окна. Нижняя навигация сохранена; используется обычный поток и safe-area/padding. Декоративный footer скрыт только на этой странице. Основные вкладки, FAB, шрифты, PNG и прочие страницы сохранены.
