# Демонстрационный frontend — этап 2

Последнее уточнение оформления: белый основной текст и голубые выделения, без видимых пометок о версии/имитации. Сами данные и действия остаются локальными; технические ограничения ниже описаны для разработчика. Прежние описания плашек и текстов кнопок относятся к предыдущему состоянию интерфейса.

После уточнения выполнены TypeScript, ESLint и сборка — успешно. Проверены 13 браузерных сценариев: 12 прошли в полном прогоне, селектор переименованной кнопки очистки в оставшемся тесте уточнён, затем этот сценарий успешно повторён. Проверка оформления охватывает белый основной текст, голубые акценты и отсутствие служебных пометок; главная просмотрена на мобильном и десктопном снимках. Фотографии и исходные PDF не изменены.

Дата: 16.11.2026. Основание — второе задание пользователя. Создан только frontend; требования полного MVP остаются в [PRODUCT](PRODUCT.md).

## Экраны

| Адрес | Поведение |
| --- | --- |
| `/` | Приветствие, начало анкеты или прямой просмотр демо. |
| `/profile` | Два шага: основные данные, затем фото, описание и три интереса; редактирование сохранённой анкеты. |
| `/home` | «Куда пойдём?», четыре раздела, основной план и подборка карточек. |
| `/catalog` | Сценарии с фотографиями, фильтры по категориям и состояние фильтра в URL. |
| `/people/:planId` | Демоанкеты, «Пойдём?» и «Следующий», ожидание ответа и отдельная имитация ответного согласия. |
| `/create` | Детали плана, валидация, предпросмотр, возврат к редактированию и локальное сохранение. |
| `/plans` | Собственные и выбранные планы; фильтры «Все», «Мои идеи», «Выбранные», «Мэтчи»; пустые состояния. |
| `/inspiration` | Три идеи; переход в создание с предварительно заполненными названием, категорией и местом. |
| `/match/:inviteId` | Экран только для сохранённой имитации двух согласий; кнопка общения объясняет будущий переход и никому не пишет. |

Есть верхняя навигация, мобильная нижняя навигация, доступ к анкете, сброс локального демо с подтверждением, обработка неизвестного маршрута и отсутствующего плана/мэтча. Все действия работают без API.

## Данные и ограничения

- Статические примеры находятся отдельно в `frontend/src/data/demo.ts`, идентификаторы начинаются с `demo-`. Имена, описания и связь людей со сценариями вымышлены. Фотографии — иллюстрации из презентации, не профили Telegram-пользователей.
- Введённые анкета и фото, собственные/выбранные планы и имитации согласий сохраняются только в localStorage под ключом `poidem:demo:v1`. Собственные планы имеют префикс `local-`. Сеть для отправки этих данных не используется.
- При недоступном/переполненном хранилище показывается предупреждение: данные доступны в памяти до перезагрузки. Некорректные сохранённые данные не должны ломать запуск.
- «Пойдём?» — односторонний локальный интерес. Экран демомэтча появляется после отдельной кнопки «Имитировать ответное согласие». Это не реальная взаимность и не серверная защита доступа.
- Нет backend, Telegram-авторизации, PostgreSQL, бота, реальных уведомлений, публикации планов, контактов, переписки, опроса или административной аналитики.

## Допущения только для прототипа

Они не закрывают вопросы Q01–Q12 для реального продукта:

- Имя: 1–40 символов. Возраст: целое число от 18, без установленного верхнего предела; это валидация ввода, не подтверждение возраста.
- Пол: женский/мужской/другой. Предпочтения: девушки/парни/все. Демоподбор учитывает взаимные предпочтения статических анкет и общий сценарий; для собственных планов кандидаты не выдумываются.
- Фото: одно JPG/PNG/WebP до 3 МБ с проверкой декодирования; описание: 1–300 символов; ровно три разных интереса из восьми примеров ТЗ. Есть заполнение готовым примером.
- Название плана: 1–80 символов, место: 1–160. Дата/время обязательны и должны быть в будущем. Описание необязательно, до 300 символов. Изменить данные можно на предпросмотре перед сохранением; отмена и редактирование опубликованного плана не добавлены.
- Москва — демонстрационная география каталога. Геолокация и расстояния не запрашиваются; бронирования не создаются. Даты каталога задаются относительно даты открытия приложения. Дата собственного плана использует подписанный в форме часовой пояс устройства.
- «Мои планы» объединяет выбранные сценарии, свои идеи и состояния демонстрационных согласий.

## Telegram WebApp

Официальный SDK загружается асинхронно. Обрабатывается уже доступный и поздно загруженный SDK; при его недоступности работает самостоятельный браузерный режим.

Используются `ready()`, `expand()`, стабильный viewport, safe area/content safe area и события их обновления. Методы цветов и нативной кнопки «Назад» проверяются через `isVersionAtLeast`. Обработчики снимаются при смене маршрута/размонтировании. Данные Telegram не используются как доверенная личность; авторизации нет.

Сигнатуры и ограничения проверены по [официальной документации Telegram](https://core.telegram.org/bots/webapps), совместимость среды — по [документации Vite](https://vite.dev/guide/). Firecrawl не поддержал страницу Telegram, она прочитана напрямую через веб-инструмент.
