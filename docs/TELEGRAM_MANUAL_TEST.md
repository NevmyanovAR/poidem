# Этап 3.5: настоящий Telegram-вход через временный HTTPS

Статус на 22.11.2026: основной ручной прогон двух настоящих Telegram-аккаунтов завершён по подтверждениям пользователя и серверным проверкам. Вход, анкеты/фото, восстановление/редактирование, изоляция и удаление проверены; источники подтверждений и ограничения приведены в итогах ниже. Среда запущена заново, все 3 HTTPS-теста прошли. Разработка планов/мэтчей требует отдельной команды и согласования зависимых правил. Дизайн и бизнес-логика не изменялись. Production-деплой, commit и push не выполнялись.

## Схема

```text
Telegram Mini App
  → HTTPS https://<случайный-host>.trycloudflare.com
  → cloudflared → HTTP 127.0.0.1:5173 (Vite)
                    └─ /api/* → HTTP 127.0.0.1:8001 (настоящий FastAPI)
                                      └─ PostgreSQL 127.0.0.1:5432
```

Для браузера приложение и API находятся на одном HTTPS-origin. Сессионная cookie — host-only `__Host-poidem_session`, Secure, HttpOnly, SameSite=Lax, Path=/; её значение не нужно копировать. Внутреннее HTTP-соединение к backend остаётся на loopback. Порт 8002 и serve_test_api.py на этом этапе не используются.

Quick Tunnel работает, пока запущен cloudflared; при новом запуске адрес меняется. Ссылка доступна получившему её человеку, поэтому используем только тестовые аккаунты/данные и не распространяем адрес. Основание — [официальная инструкция Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## Подготовка и точные команды Windows PowerShell

Ниже используются уже установленные `.venv`, frontend-зависимости и существующий игнорируемый `.env`. Для чистого клона первичная установка — [backend/README](../backend/README.md). Все терминалы начинают работу в `C:\Users\arthur\Desktop\poidem`. Не запускайте вторую копию на занятых портах; при повторной настройке backend/Vite нужно остановить и запустить заново.

### 1. PostgreSQL и миграции

Если Docker Desktop не запущен:

```powershell
Start-Process -FilePath "C:\Program Files\Docker\Docker\Docker Desktop.exe" -WindowStyle Hidden
```

Дождитесь готовности Docker Desktop, затем:

```powershell
Set-Location C:\Users\arthur\Desktop\poidem
docker version --format '{{.Server.Version}}'
docker compose up -d --wait db
.\backend\.venv\Scripts\python.exe -m alembic -c .\backend\alembic.ini upgrade head
.\backend\.venv\Scripts\python.exe -m alembic -c .\backend\alembic.ini check
```

Compose публикует PostgreSQL только на 127.0.0.1:5432. Туннель направлен только в 5173, не в PostgreSQL/5432, backend/8001 или тестовый API/8002. Не меняйте привязку БД на 0.0.0.0.

### 2. Действующий токен — скрытый ввод

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Set-TelegramToken.ps1
```

Введите действующий токен нужного бота. Не вставляйте его в командную строку/чат и не выводите `.env`. Изменение токена требует перезапуска backend. Ранее переданный в чат токен желательно перевыпустить через BotFather. Без действующего токена ручной вход нельзя считать проверенным.

### 3. Quick Tunnel — отдельный терминал, оставить работающим

```powershell
Set-Location C:\Users\arthur\Desktop\poidem
.\backend\.venv\Scripts\python.exe .\scripts\quick_tunnel.py --install
.\backend\.venv\Scripts\python.exe -u .\scripts\quick_tunnel.py
```

Installer берёт официальный Windows x64 cloudflared 2026.11.1 и проверяет SHA-256 релизного файла. Системный PATH и Cloudflare-аккаунт не настраиваются. Бинарный файл — в игнорируемой `.tools`, только публичный адрес/PID/время — в `.local/quick-tunnel.json`. Сырые stdout/stderr cloudflared не записываются в файлы и не выводятся: wrapper пропускает только стартовый origin и фиксированные сообщения состояния. Debug-логирование не включается. Внутри используется `--output json` этой версии CLI, target строго `http://127.0.0.1:5173`, metrics — только 127.0.0.1:20241.

### 4. Применить адрес — другой терминал

Пока туннель работает:

```powershell
Set-Location C:\Users\arthur\Desktop\poidem
.\backend\.venv\Scripts\python.exe .\scripts\tunnel_config.py --apply
```

Или явно передать только публичный origin:

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\tunnel_config.py --apply --origin https://<случайный-host>.trycloudflare.com
```

В этой строке `<случайный-host>` заменяется адресом из терминала туннеля; угловые скобки не вводятся. Скрипт меняет только разрешённые публичные параметры в `.env`, не трогает токен/DB URLs/пароли и сохраняет исходные публичные настройки отдельно для восстановления.

| Переменная | Значение стенда |
| --- | --- |
| APP_ENV | development, настоящий backend |
| MINI_APP_URL | `https://<host>.trycloudflare.com/` |
| API_PUBLIC_URL | `https://<host>.trycloudflare.com/api/v1` |
| VITE_API_BASE_URL | `/api/v1`, относительный URL того же origin |
| POIDEM_API_PROXY_TARGET | `http://127.0.0.1:8001` |
| POIDEM_DEV_ALLOWED_HOSTS | JSON-массив из одного точного hostname туннеля |
| CORS_ORIGINS | JSON-массив из одного точного HTTPS-origin без пути |
| TRUSTED_HOSTS | `127.0.0.1`, `localhost`: Vite changeOrigin передаёт локальный Host |
| SESSION_COOKIE_SECURE | true |
| SESSION_COOKIE_SAMESITE | lax |

Не выставляйте wildcard hosts/origins, SameSite=None или небезопасную cookie ради обхода ошибок. Старый Pages-origin в этом прогоне не используется. Vite ограничен каталогом frontend; чтение `.env`, `.git`, `.local`, backend и references через `/@fs` запрещено.

### 5. Настоящий backend — отдельный терминал

```powershell
Set-Location C:\Users\arthur\Desktop\poidem
.\backend\.venv\Scripts\python.exe -m poidem --host 127.0.0.1 --port 8001
```

Проверка из другого терминала:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
```

В Windows нужен этот entrypoint: он задаёт SelectorEventLoop для psycopg. Сервер использует основной локальный DATABASE_URL из `.env`; синтетические токены/подмена авторизации не добавляются. Логи содержат шаблон маршрута/status/request_id, без токена, cookie, initData и тела запроса.

### 6. Vite — отдельный терминал

```powershell
Set-Location C:\Users\arthur\Desktop\poidem\frontend
npm run dev -- --logLevel silent
```

Локальный адрес — http://127.0.0.1:5173/. Silent отключает выдачу деталей запросов при ошибках proxy. На телефоне открывается HTTPS-адрес туннеля как Mini App из бота. При изменении `.env` перезапустите backend/Vite; адрес активного туннеля менять не нужно.

## BotFather

Укажите **корневой HTTPS-адрес текущего туннеля**, со слэшем в конце. Не localhost, не /api/v1 и не прежний Pages URL.

В BotFather выполните `/setmenubutton`, выберите @ShallWeGoo_bot и по его подсказкам задайте выданный URL и название «Пойдём?». Открывайте именно новую кнопку меню в чате бота. Если используете Main Mini App, задайте тот же URL и в его настройках; меню и Main Mini App — разные способы запуска. Обычная браузерная ссылка не выдаёт initData. Обработчик сообщений бота/aiogram для этого входа не требуется. Основание — [документация Telegram](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).

При новом Quick Tunnel обновите `.env` helper-скриптом, перезапустите backend/Vite и измените адрес в BotFather. Не открывайте сохранённый старый адрес.

## Ручной протокол двух аккаунтов

Не используйте реальные чувствительные описания/фотографии. Записывайте только «A/B», клиент/ОС/версию, результат и время; не Telegram ID, username, cookie или initData.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| A1 | Аккаунт A открывает Mini App из бота → анкета | «Данные Telegram подтверждены сервером»; /auth/telegram и /auth/csrf успешны |
| A2 | A вводит тестовые поля 18+, три интереса, JPEG/PNG/WebP до 3 МиБ | Сохранение переводит на home, собственное фото отображается |
| A3 | Полностью закрыть Mini App и заново открыть из бота | Сохранённая анкета/фото восстановлены, новый профиль не создаётся |
| A4 | Изменить описание/имя и сохранить, снова открыть | Изменения восстановлены; серверная версия выросла |
| B1 | Полностью закрыть приложение, сменить Telegram-аккаунт на B и открыть из бота | Подтверждён отдельный вход; нет анкеты A |
| B2 | Заполнить другую тестовую анкету/фото, закрыть/открыть | Восстановлены только данные B; изменения B не меняют A |
| P1 | В контексте авторизованного B запросить приватное фото A | HTTP 404; своё фото B — 200. Внешний браузер без сессии получает 401, это отдельная проверка |
| D1 | На A нажать «Удалить аккаунт» и подтвердить | Аккаунт приложения, профиль, фото и все его сессии удалены; сам Telegram-аккаунт остаётся |
| D2 | Открыть A заново и проверить B | У A пустая новая анкета, прежнее фото недоступно, B сохранён |
| M1 | Проверить отсутствие переключателя/заполнения примером, старые ссылки/флаги | Деморежим удалён; вымышленные данные не появляются |

После D1 повторный вход A создаёт новый пустой аккаунт приложения — это ожидаемо. Для проверки отзыва **старой** сессии сначала проверьте её на другом устройстве A, не выполняя на нём новый вход. Обновление страницы Mini App может автоматически выполнить новый вход; это не доказательство сохранения старой сессии.

Для P1 откройте WebView DevTools на B по [официальным инструкциям Telegram](https://core.telegram.org/bots/webapps#debugging-mini-apps). Выполняется запрос в том же Mini App, не перенос cookie в curl/чат. Сначала проверьте 200 для `/api/v1/me`, затем подставьте только UUID тестового фото A:

```javascript
await fetch('/api/v1/me', { credentials: 'include', cache: 'no-store' }).then(r => r.status)
await fetch('/api/v1/media/photos/<photo-a-uuid>', { credentials: 'include', cache: 'no-store' }).then(r => r.status)
```

Первая строка должна вернуть 200, вторая 404. Не выводите response body /me, cookie, initData или CSRF. Если WebView-инспектор на доступном устройстве недоступен, P1 остаётся **не пройденным вручную**, даже при успешных прежних автоматизированных ownership-тестах. Аналогично отзыв старой сессии нельзя объявлять проверенным по одной перерегистрации.

## Остановка и восстановление

В своих терминалах остановите tunnel, Vite и backend через Ctrl+C, затем:

```powershell
Set-Location C:\Users\arthur\Desktop\poidem
.\backend\.venv\Scripts\python.exe .\scripts\tunnel_config.py --restore
```

Скрипт восстанавливает только прежние публичные настройки, сохраняя последний введённый токен и DB-пароли. После этого новый локальный backend/Vite запускаются со старой конфигурацией. `.local` и `.tools` исключены из Git, исходные PDF/дизайн не изменяются. PostgreSQL можно оставить для разработки либо остановить `docker compose stop db`; `down -v` не нужен.

Если туннель был запущен агентом и его терминал недоступен, закрыть **только этот cloudflared** можно с проверкой пути:

```powershell
$poidemTunnel = Get-Content .\.local\quick-tunnel.json -Raw | ConvertFrom-Json
$poidemTunnelProcess = Get-Process -Id $poidemTunnel.cloudflared_pid -ErrorAction SilentlyContinue
$poidemTunnelExe = (Resolve-Path .\.tools\cloudflared.exe).Path
if ($poidemTunnelProcess -and $poidemTunnelProcess.Path -eq $poidemTunnelExe) {
    Stop-Process -Id $poidemTunnelProcess.Id
}
```

Не завершайте все процессы Python/Node и не удаляйте volume БД. Закрытие cloudflared прекращает внешний доступ; backend/Vite привязаны к loopback.
