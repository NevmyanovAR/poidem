# Карточки, роли и обновление архива — D51

Актуализация 25.11.2026: [D52](RESPONSE_HISTORY_UX.md) заменяет вывод accepted в «Полученных»/«Выбранных» компактной историей остальных результатов; пары остаются в «Мэтчах»/«Все»/архиве. В архиве добавлен просмотр всей истории автора. Ниже сохранён отчёт D51

24.11.2026. Изучены задание и все семь новых PNG в references/review:
окончания имён 01_03_09, 01_03_21, 01_03_30, 01_03_42, 01_03_49,
01_03_57, 01_04_04. Исходные изображения не изменялись и не копировались в приложение.
Имена/фото с пользовательских скриншотов не добавлялись в тестовые fixtures.

## Причины

1. ResponseCard выводил accepted как обычный отклик с описанием/интересами и одним
   действием, MatchCard — как другую сущность с другим набором ссылок
2. Общий текст rejected не учитывал роль. После отказа profile намеренно недоступен,
   а собственного исторического имени/возраста кандидата не было
3. Отклонённому plan/profile возвращаются null согласно D50. Исторического контекста
   не было, поэтому UI показывал большой заголовок «Автор отклонил отклик»
4. min-height карточки, grid stretch/flex:1, растянутое фото, внешний gap и неравномерные
   внутренние padding делали короткие записи пустыми, а длинные — тесными
5. Мобильный .filter-row одновременно использовался для навигации и интересов.
   nowrap/горизонтальная прокрутка и overflow карточки обрезали теги
6. .text-link:hover менял gap с 9 до 13 px, перестраивая ширину ссылки/строку действий
7. Разные форматировщики отдельно собирали дату/время, иногда добавляли IANA-идентификатор
8. Активная вкладка не удерживалась в видимой области после изменения ширины/загрузки
   Manrope. Прокрутки строки и страницы не были явно разделены
9. В архиве переключатель стоял раньше обновления, отсутствовал отдельный заголовок.
   Прямого location.reload не найдено. Смена key после команд пересоздавала ленту;
   временные загрузочные строки и изменения композиции усиливали ощущение перезагрузки

## Изменённые данные и API

Миграция **0006_response_history_context.py**, head 0006. Без новых таблиц,
удаления записей, downgrade или очистки volumes. У прежнего PlanResponse добавлен
nullable JSONB history_context. Прежние 33 таблицы и авторизация сохранены.

Новые отклики сохраняют только plan_title, author_name, responder_name, responder_age,
captured_at и source=response. Снимок формируется сервером после проверки реального
пользователя и доступных анкет; из JSON клиента эти поля не принимаются. Он не меняется
при редактировании плана/анкеты. Фото, bio, интересы, контакты и Telegram ID не копируются.

Пользователь отдельно согласовал старую историю: один снимок доступного текущего
контекста при миграции с **source=legacy** и подписью «Сведения сохранены позже отклика».
Это не восстановление точных значений на момент старого отклика. Перенос идемпотентен,
существующие снимки не перезаписываются; недоступные/ограниченные модерацией данные
не восстанавливаются. Если контекст нельзя сохранить безопасно, поле остаётся null
и UI честно сообщает, что имя/название не сохранено.

Новых endpoints нет. Дополнены действующие DTO:

- ResponseDTO: viewer_role=author|responder, history_context, match (MatchDTO для accepted)
- MatchDTO: viewer_role=author|responder для определения второго участника

Роль вычисляется по серверной сессии и участникам записи. Входящая/исходящая вкладка,
клиентский Telegram ID или подпись карточки роль не определяют. Вложенный match
устраняет гонку между загрузкой истории откликов и отдельной коллекции мэтчей.

У rejected отправителю по-прежнему plan=null/profile=null, прямые детали/фото плана
недоступны. Исторический текст не содержит ссылки на скрытый план. Другие планы автора
доступны; повторный отклик запрещён на backend, UNIQUE и лимит 15 ожиданий не менялись.

## Единые карточки

Общие только рамка/фото, метаданные и стрелка. Представления разделены:

| Представление | Содержание и действия |
| --- | --- |
| Собственный план/черновик | Статус, название, дата/место; просмотр и входящие отдельно от изменения/публикации/явной отмены |
| Ожидающий входящий | Название, кандидат и возраст, метаданные, bio/интересы; Принять/Отклонить по роли/статусу |
| Ожидающий исходящий | Название, автор и возраст, метаданные, bio/интересы; Посмотреть пару |
| Подтверждённый мэтч в любом разделе | Название, имя/возраст партнёра, дата/место, unread; Написать/Подробнее, без bio/интересов |
| Отклонённый входящий | Вы отклонили отклик; название плана, конкретное имя/возраст кандидата из снимка; без текста о повторном отклике |
| Отклонённый исходящий | Ваш отклик не принят; название плана, автор из снимка, короткое пояснение; без ссылок на план/анкету |
| Архив | То же представление по типу записи плюс персональное Скрыть/Восстановить; переписка не удаляется |

Порядок внутри карточки: небольшой статус → название Forum → имя/возраст → дата/место →
дополнительные сведения при необходимости → действия. Spacing/typography карточек —
общие токены theme.css. Высота зависит от содержимого; min-height, растягивание короткой
карточки и обрезающий overflow убраны. Фото имеет согласованные ширину и пропорции,
не растягивается на всю высоту длинного текста.

recordActions.ts — единая политика UI-действий по типу, серверной роли и статусу;
она не заменяет серверные проверки. MatchActions/MatchCard используются и для accepted
истории, и для самостоятельных мэтчей, и для «Все»/архива.

«Написать» ведёт прямо в /match/{id}/chat. «Подробнее» — /match/{id}. Telegram-кнопка
сохранена только на подробном экране при доступном username; чат работает без него.
Синхронизации встроенных сообщений с Telegram нет. Bio/интересы партнёра добавлены на
подробную страницу мэтча, где они разрешены существующим контекстом согласия.

## Даты, навигация и геометрия

meetingDateLabel использует реальный starts_at и IANA-зону API, единообразно для карточек
плана/отклика/мэтча, каталога, анкеты автора, подробностей и предпросмотра. Пример:
«22 февраля 2027, 12:12»; год текущего года опускается. Учитываются смена года и DST.
UTC/IANA в PostgreSQL/API не изменены. Технический идентификатор зоны из карточек убран.

Стрелке выделена постоянная область 20×20. Только svg смещается transform на 3 px при
hover/focus/active, gap/margin/padding/width не меняются. Карточки/текст не сдвигаются.
Для prefers-reduced-motion движение отключается. У главной кнопки карточки убран
унаследованный подъём всей кнопки при hover; другие утверждённые кнопки не переделывались.

interest-tags — отдельный flex-wrap контейнер с ограничением ширины; длинные названия
переносятся внутри тега. Profile interest-chips также допускает перенос длинного текста.
Навигационные plans-tabs на сенсорных экранах остаются горизонтально прокручиваемыми, без скролла страницы. По уточнению 24.11 на ПК (hover/fine pointer) вкладки переносятся на строки; системный ползунок скрыт для всех браузеров. В опубликованных собственных планах убрана нижняя черта у «Отменить план»; другие действия сохранены.
Активная вкладка удерживается внутри строки, включая загрузку шрифтов/resize; window
не прокручивается. Перенос действий и длинного содержимого проверяется на мобильных.

## Архив

Порядок: «Архив» → кнопка обновления → «Показать скрытые» → список. Основная навигация
между разделами остаётся на своём месте. Кнопка обновляет только API-данные, показывает
aria-busy/«Обновляем…» в постоянной области и блокирует повторное нажатие на время запроса.
Прежние карточки остаются на экране, ошибка локальна, основной layout/nav не размонтируются.
Прежний key пользователя/раздела сохраняется; изменение данных после отмены больше не
меняет key ленты. Неавторизованные/чужие данные по-прежнему очищаются при потере контекста.

При временной ошибке обновления связанных коллекций provider сохраняет уже загруженные
записи; при 401/смене аккаунта они очищаются. Это не fallback из локального хранилища.
Персональное скрытие/восстановление, фоновые семь дней и судьба переписки не менялись.
