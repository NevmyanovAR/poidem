# Этап 11Б — добровольная ручная фотоверификация (D65)

## Подтверждённый объём и ограничения

Пользователь разрешил ручную сверку основной фотографии с проверочным селфи, очередь внутри прежнего /admin, положительную отметку «Фото подтверждено», сброс при замене фото и сообщения через прежний notification_jobs. Проверка добровольная. Это не установление личности/возраста, не автоматическое распознавание лица, не биометрический шаблон и не гарантия безопасности. Внешних сервисов/ключей/платных API нет. Places/D64, опыт D58, планы/мэтчи/чаты и основной процесс регистрации не меняются.

**По умолчанию реальный сбор выключен.** В продолжении от 27.11.2026 локальный .env уже предоставлен с обоими разрешающими флагами, consent_version=pilot-v1, текстом согласия, ожиданием 72 часа и хранением после решения 0 часов. Эти настройки использованы без подмены тестовыми значениями; API перезапущен для их загрузки. На экране до согласия дополнительно показаны реальные сроки, отдельно от текста согласия. Они не становятся автоматически production-политикой: перед отдельной публикацией нужны решения владельца для production и его инфраструктуры. В .env.example defaults сохраняются выключенными.

## Пользовательский процесс

Настройки → «Подтвердить фото» → объяснение и согласие → серверная случайная инструкция → камера → просмотр/пересъёмка → отправка → «Фото на проверке». Файл из галереи не заменяет камеру; существующая регистрационная загрузка фото сохранена отдельно. Пример кадра — небольшой векторный контур лица/плеч, хорошее освещение, видимость лица и жеста; документы не требуются.

Камера использует getUserMedia, facingMode=user, без аудио, playsInline/muted, локальный canvas → JPEG. Передача начинается только после отдельного нажатия «Отправить на проверку». Поток останавливается при съёмке, закрытии, уходе со страницы и переходе приложения в фон; запоздалый ответ камеры после ухода закрывается. Blob URL уничтожается при пересъёмке/уходе. Снимок не пишется в localStorage/IndexedDB. Есть понятный отказ доступа; запасного выбора галереи нет.

[Официальное описание getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia): необходимы разрешение и secure context (HTTPS, локальный localhost); доступ может дополнительно ограничивать WebView/родительская Permissions Policy. Приложение не может снять ограничение клиента Telegram. Обычная камера и случайная инструкция не доказывают отсутствие подделки; API также не может достоверно установить, каким способом клиент получил файл. Наличие лица и соответствие жесту оценивает человек.

Состояния UI: Не подтверждено / Фото на проверке / Фото подтверждено / Заявка отклонена / Проверка недействительна после смены фотографии. Первое — нейтральный текст, без штрафов или подозрений. При ошибке не подставляются примеры. Обновление использует прежний foreground clock, без второго polling-интервала; съёмка и несохранённый кадр не прерываются фоновым обновлением статуса.

## Привязка и серверный жизненный цикл

Миграция 0012 поверх 0011: profiles.photo_revision=1 для существующих анкет и одна новая таблица photo_verifications (37 прикладных таблиц). Никаких старых подтверждений задним числом.

Заявка хранит владельца из сессии, UUID/ревизию/версию содержимого основной Photo, серверный жест, согласие/его версию и текст/дату, created/submitted/expires/reviewed, решение/модератора/причину, минимальные приватные ссылки на материалы и срок очистки. Не сохраняются векторы, эмбеддинги, документы или чужие контакты.

Состояния БД: pending, approved, rejected, cancelled, expired. До съёмки это pending без submitted_at и без файлов; такая запись не попадает к модератору. Повтор создания возвращает ту же актуальную заявку; повтор отправки не перезаписывает снимки и не создаёт новую строку. Частичный UNIQUE(user_id) WHERE state='pending' защищает параллельные запросы. Весь процесс сериализуется прежней блокировкой User, решение дополнительно блокирует заявку; версия защищает устаревшее решение.

Технические ограничения: инструкция 600 секунд, до 3 новых попыток за скользящие 24 часа, загрузка до 6 запросов за минуту; первые два значения настраиваются. Это ограничения нагрузки, не санкции и не показатель надёжности. Повтор текущей заявки не расходует новую попытку. Формат/размер/пиксели/анимация/соответствие MIME и содержимого проверяются прежним Pillow: JPEG/PNG/WebP, до 3 МБ и 16 MP, нормализованный JPEG без EXIF/ICC/комментариев.

Положительная отметка вычисляется из approved + текущих photo_id/photo_revision/Photo.content_version + отсутствия отзыва согласия. Это не присылаемый клиентом флаг. Смена основной фотографии при сохранении анкеты увеличивает photo_revision, переводит прежние pending/approved в expired с причиной photo_changed и снимает доступ к материалам в той же транзакции. Одна временная загрузка без сохранения анкеты не заменяет основное фото. Описание/интересы/имя не сбрасывают отметку.

Для сравнения сохраняется временная приватная копия именно основной фотографии на момент отправки, а не ссылка на меняющийся текущий портрет. После окончания хранения approved может оставаться действительным без хранения изображений. Публичные DTO содержат только photo_verified, никаких селфи/причин/согласий. Отметка показывается в собственной анкете, подробностях чужого плана и входящем отклике. По нажатию: «Фотография анкеты сверена с проверочным селфи модератором. Это не проверка личности по документам». Подпись авторизации переименована в «Вход через Telegram»; проверка HMAC и сессии прежняя.

## Модератор

Прежний /admin → Модерация → «Проверка фото». Права moderation у moderator/admin/owner проверяются сервером на каждом запросе; analyst/user доступа к очереди и снимкам не имеют. Дополнительных ролей или отдельной админки нет. Собственную заявку нельзя рассматривать самому.

По умолчанию pending: имя, дата, время ожидания, открытие заявки, серверная пагинация; есть фильтры approved/rejected. В деталях два снимка рядом с сохранением пропорций и прежним полноэкранным PhotoViewer. Одобрение и отказ требуют подтверждения действия; отказ — причину, для other обязательный комментарий. Причины: несовпадение лиц, плохая видимость, несоответствие инструкции, недостаточно данных, другая. Нет публичных обвинений или санкций.

Решения/read/photo_read пишутся в прежний административный аудит без изображений или ключей файлов. Две параллельные операции не создадут два решения. После замены основной фотографии одобрение прежней заявки возвращает 409. При смене роли после открытия заявки запись/чтение повторно проверяют права.

## Приватность, отзыв и удаление

MEDIA_ROOT общий и приватный, прежние write_photo/media_path/Pillow/orphan scan/MediaDeletion. Материалы заявки не создают публичную Photo и не входят в публичные карточки, аналитику или CSV. Owner endpoint доступен только владельцу и только для текущего необходимого pending-процесса. Admin URLs требуют сессию и moderation, не являются постоянными публичными ссылками. Cache-Control=no-store; отсутствие/истечение/удаление дают 404.

pending после срока → expired и очередь удаления. После решения применяется сохранённый в заявке срок reviewed retention; 0 означает немедленное снятие доступа и постановку файлов на удаление. Истечение срока хранения картинок не снимает уже действующее подтверждение текущего фото. Даже ограниченный аккаунт может отозвать согласие. Отзыв согласия через текущую заявку отзывает согласия на собственные проверочные материалы, очищает их и снимает отметку. Устаревшая версия/появившаяся новая заявка требуют обновления, чтобы не отозвать незаметно новое согласие.

Файлы удаляются существующим циклом очистки (обычно до 30 секунд, ошибки I/O повторяются); ссылки блокируются сразу после транзакции. При удалении аккаунта собственные verification-записи и их уведомления удаляются, все ключи включаются в прежнюю очистку файлов. Прежний B13 для совместных планов/мэтчей/аудита не ослабляется. Фото/селфи не выдаются другому пользователю через старый /media/photos.

**Резервные копии:** backup_local теперь копирует только ключи Photo/EditorialIdea, существующие в основной БД после подтверждённой остановки writers. Временные селфи и копии основного портрета для сравнения не входят в новые архивы; orphan-файлы и ожидающие удаления материалы тоже исключены. Manifest фиксирует исключение. Проверочные материалы после восстановления не восстанавливаются, незавершённую заявку потребуется отозвать/создать заново. Уже существующие архивы не изменяются: при наличии старых копий до обновления нужно отдельно проверить их состав/доступ/ротацию; нельзя обещать удаление ранее созданных копий за 30 секунд.

## Уведомления

Два новых kind в прежнем notification_jobs: photo_verification_approved и photo_verification_rejected. Создаются транзакционно с решением; dedupe_key содержит UUID/результат. Никакой второй очереди/механизма. Старые opt-out, private binding, lease/fencing/retry/suppress остаются; устаревшая проверка, сменённое фото, отзыв согласия или новая попытка подавляют старое уведомление. Статус всегда читается из API независимо от бота.

«Фото подтверждено» → краткая сверка с селфи → «Посмотреть результат».
«Проверка фото не пройдена» → причина → «Можно попробовать ещё раз» → «Переснять фото».

Обе кнопки ведут непосредственно в /settings/photo-verification; причина экранируется HTML, селфи не отправляется в бот. Mocked Bot API/формирование payload не выдаются за настоящую доставку Telegram.

## API

Префикс /api/v1. Сессия/account context обязательны; POST дополнительно Origin/CSRF. Нельзя передавать user_id/статус/версию основной фотографии.

| Метод | Путь | Действие |
|---|---|---|
| GET | /me/photo-verification | Доступность, текущий статус и минимальная собственная заявка |
| POST | /me/photo-verification/challenge | {consent_version, consent_accepted:true}; серверная инструкция |
| POST | /me/photo-verification/{id}/selfie | multipart только file; повтор не создаёт копию |
| GET | /me/photo-verification/{id}/selfie | Только владелец/необходимый pending-процесс |
| POST | /me/photo-verification/{id}/withdraw | {expected_version}; отзыв и снятие доступа |
| GET | /admin/photo-verifications | state=pending/approved/rejected, offset/limit |
| GET | /admin/photo-verifications/{id} | Контекст, два защищённых URL, can_decide |
| GET | /admin/photo-verifications/{id}/photo/{primary,selfie} | Только moderation, аудит чтения |
| POST | /admin/photo-verifications/{id}/decision | expected_version, decision, reason_code/comment при отказе |
