# Этап 10 — пользовательские карточки, фотографии и обновление

## Объём и сохранённые решения

Подтверждённое задание пользователя: улучшить существующий UX после этапа 9Б, без изменения правил знакомств, дизайна, административного кабинета и архитектуры. Вопросы в процессе не задавать, нерешённое записывать для последующего согласования.

Серверный порядок собственных идей и отдельный диалог каждого мэтча уже работали по D60, поэтому повторная система не создавалась. Сохраняются пять нижних вкладок, глобальный плюс, окончательный отказ D50, блокировки/модерация, 3 создания за сутки, 15 ожидающих, одна пара на план, чаты, опросы и самоотчёты D58. Избранного в актуальном приложении нет — оно не добавлялось. Деморежим остаётся удалённым.

## Фактические изменения

- Своя идея: фотография крупнее, название/дата/место, один статус, одно главное действие. При ожиданиях — «Посмотреть отклики (N)» прямо в кандидаты выбранного плана. Пустые ссылки входящих убраны. Изменение и отмена в компактном меню с закрытием снаружи/Escape.
- `PlanDTO.allowed_actions` возвращает разрешённые прежними проверками команды. При чужой записи, архиве, закрытии, ограничениях автора/анкеты/плана или любой истории откликов/мэтчей список пуст. UI при отсутствии поля ничего не предполагает. Сами команды по-прежнему проверяют владельца, состояние, версию и данные транзакционно.
- Полученные отклики: акцент на фотографии и имени/возрасте кандидата, затем плане и коротком описании. Полная анкета и интересы в прежнем `Modal`, доступны до решения. Принятие/отказ и контекст безопасности сохранены.
- Собственные идеи: опубликованные с решениями → остальные будущие опубликованные по ближайшей встрече → черновики → компактная история. У архива общий порядок от нового события к старому до пагинации, без приоритета вида записи. История/скрытие не удаляются из БД.
- Диалоги компактнее: портрет, имя/возраст, план, последнее сообщение («Вы:» для собственного), время/достоверное непрочитанное и небольшой переход «О встрече». Два плана с одним собеседником остаются двумя диалогами, пустой чат тоже доступен.

Основные файлы: `PlanCards.tsx`, `ActivityFeed.tsx`, `PhotoViewer.tsx`, `RecordMenu.tsx`, страницы `MyPlans/Chats/People/Match/Catalog`, `ApiProvider.tsx`, `App.tsx`, `main.tsx`, `styles.css`, `autoRefresh.ts`, `scrollMemory.ts`, `recordActions.ts`, `telegram.ts`, клиент API/типы. Backend: только `schemas/plan.py`, `services/plans.py`, `services/activity.py` и новый `test_user_ux_stage10.py`. Добавлен браузерный `user-ux-stage10.spec.ts`, обновлены контрактные фикстуры/селекторы прежних проверок и каталоги артефактов Playwright. README/AGENTS, PRODUCT/DECISIONS/API_CONTRACT/ROADMAP обновлены. Новых endpoint, таблиц и миграций нет; head **0010**.

## Фотографии и Back

Единые `ProfilePhoto`/`PhotoViewerProvider` подключены к автору плана, кандидату входящего отклика и существующим портретам участников мэтча. Используется только уже выданный защищённый URL. Нового фото-API/публичного каталога/Telegram-аватара/подмены случайным изображением нет.

Native dialog поверх страницы: `object-fit: contain`, полупрозрачная фирменная подложка, safe-area, закрытие кнопкой/подложкой/Escape. Временная запись History API имеет тот же URL; в состоянии только технический маркер поверх существующего Router state, без фото/анкет/initData. Browser Back закрывает просмотр, Telegram Back сначала передаёт его открытому overlay. Исходный экран не размонтируется, прокрутка и фокус возвращаются. При смене пользователя/контекста просмотр закрывается; ошибка загрузки показывает нейтральную заглушку без запасной фотографии. Нижняя навигация под модальным окном неактивна, глобальный плюс скрыт во время фото/модального окна/меню.

## Обновление и возврат

Один прежний таймер `ApiProvider` раз в 30 секунд, только при видимой странице, обновляет счётчики и посылает foreground-событие текущему экрану. Те же события приходят при `focus`/возвращении из фона. Каждый экран загружает данные при входе, после успешных команд используется прежний `activityRevision`/обновление соединений. Отдельные циклы списков удалены; существующий polling открытого чата сохранён.

`RefreshGate` разрешает один выполняющийся запрос и максимум одно последнее отложенное обновление. Во время фоновой загрузки сохраняются карточки; сетевой сбой не заменяет их пустым состоянием. При ошибке есть понятное сообщение и «Повторить загрузку», в штатном интерфейсе технических кнопок обновления нет. Утрата авторизации или доступа обрабатывается отдельно от временной сети.

Поколение запроса меняется при постановке обновления в очередь, поэтому запоздалый ответ уже заменённого запроса не возвращает устаревшие карточки/сообщения на экран. Отдельный браузерный тест задерживает такой ответ и проверяет, что он ни на один кадр не заменил актуальный контекст.

Положение списка и число уже загруженных строк сохраняются только в памяти процесса по маршруту/фильтру. При возвращении сначала восстанавливается объём списка и затем доступная прокрутка; данные аккаунта в storage не сохраняются. При смене аккаунта эта память очищается. После перезагрузки вкладки возврат к прежнему пикселю не обещается.

## Исправленные UX-проблемы

| Было | Стало |
| --- | --- |
| Меню предлагало редактирование при уже существующей истории откликов | Отображение команд по серверной проекции прежних прав |

## Отложенные вопросы

Новых бизнес-решений для этого UX-этапа не требуется. Уже открытые B13 (совместная история при удалении аккаунта, сроки хранения/согласия), B14 (окончательные HTTPS-адреса и размещение), будущие полномочия по спорам и автоматические изображения планов остаются для отдельного согласования. Никакого TTL/90 дней, удаления истории, новых санкций или изменений лимитов здесь нет. Commit, push и публикация не выполняются.

На предыдущей попытке запуска после паузы Docker оставался в состоянии `starting`, Engine отвечал HTTP 500, а `/health` — 503. Та попытка не засчитана как успешная проверка API или повторный pytest; 102 теста выше реально прошли до паузы на отдельной PostgreSQL. Данные/volumes/настройки не сбрасывались. Это ограничение устранено последующим запуском, описанным ниже.
