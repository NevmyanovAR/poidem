# Страница автора плана и отметка опыта — D59

Прямое задание пользователя после этапа 8: сделать главным человека, сократить путь
до отклика и показывать публично только наличие подтверждённого опыта.
Это изменение frontend, не новый функциональный этап

## Страница /people/:planId

- Главная фотография — photo из существующего защищённого GET /plans/{id}/author;
  изображение выдаётся прежним /plans/{id}/author/photo с проверкой доступа
- Telegram-аватар/фото категории не используются вместо анкеты. Статических копий
  пользовательских фото и публичного media endpoint не добавлено
- При пустом URL или ошибке загрузки — нейтральный UserRound и «Фото пока недоступно».
  При недоступности самой анкеты сохраняется прежнее защищённое пустое состояние,
  ограничения сервера не обходятся
- object-fit:cover, позиция 50% 18% с предпочтением верхней части портрета;
  без искажений, автоматического распознавания лица или заявлений о проверке личности
- На мобильном фото 190–260 px по высоте, скругление и прежний бордовый градиент.
  Десктоп сохраняет две колонки: портрет и сведения/действие
- Затем имя/возраст с явной запятой и меньшим размером, отметка опыта при наличии,
  единственное название плана, дата/место и прежнее главное действие
- Биография, интересы и описание плана находятся в раскрываемом «Об авторе и плане»
  после действия, без новой страницы и повторения названия
- Возврат, обновление, переход «Следующий план», сердце и SafetyMenu сохранены.
  У перехода к следующему плану прежнее назначение — каталог
- Декоративный site-footer убран только для /people/*; шапка/PNG и нижняя навигация
  сохранены. Отступ внизу main учитывает навигацию/safe area; новой фиксированной
  панели действий нет. Остальные страницы не меняют footer

Обработчик отклика, Idempotency-Key и disabled={busy || !capacity.canRespond}
не изменены. Лимит 15, состояние собственного ожидания, профиль и персональные
блокировки по-прежнему проверяет backend. При canRespond=false без исчерпания
лимита выводится нейтральное «Сейчас откликнуться на этот план нельзя»:
клиент не угадывает, связано ли это с блокировкой или анкетой. Фото с ошибкой
отображения само по себе не меняет серверную доступность отклика

## Отметка опыта

Решение D59 заменяет публичное числовое отображение D58:

- При unique_confirmed_partners > 0 — «Есть подтверждённые встречи»
- По нажатию — «Участники хотя бы одной встречи подтвердили, что встретились»
- При нуле/отсутствии данных отметка не создаётся в DOM; отрицательного статуса нет
- В публичном UI нет точного числа, в том числе в aria-label/title
- Собственная анкета сохраняет личное число из GET /me/reliability

Правило распространяется на существующий ExperienceCaption страницы плана и анкеты
партнёра в мэтче. Это не рейтинг, верификация личности или гарантия безопасности

Расчёт D58, исходные ответы, уникальность пары и backend не менялись. Прежнее
числовое поле experience в JSON используется для условия >0; новой серверной
политики сокрытия этого поля/нового API, таблиц и миграций не вводилось
