## Блокировки и идентификация

Прежний GET `/api/v1/me/blocks` расширен только данными представления:

| Поле | Смысл |
| --- | --- |
| id | Прежний ID **связи блокировки**, только он используется для DELETE |
| name | Имя, разрешённое существующим контекстом/прежним API |
| age | Возраст из разрешённого мэтча либо замороженного контекста отклика, иначе null |
| photo_url | Прежний защищённый URL фото участника собственного мэтча, иначе null |
| context | Существующее название плана из общей истории отклика/мэтча, иначе null |
| context_saved_later | Честная пометка source=legacy, если снимок был сохранён позже отклика |
| display_code | Стабильный короткий код аккаунта, без раскрытия Telegram ID/UUID/контактов |
| created_at | Прежнее время блокировки |

Код вычисляется из высокоэнтропийного UUID аккаунта через SHA-256 с отдельным namespace,
первые 12 Base32-символов разбиты на три группы. Он не является обратимым кодированием
UUID и не меняется при перезагрузке, повторной блокировке или ротации токена бота.
Это вспомогательное различение в интерфейсе, а не доказательство личности или ключ авторизации

Список содержит только собственные активные персональные ограничения. Совпадение
имени/возраста не влияет на выбор: подтверждение показывает имя, код и имеющийся контекст;
запрос и локальное удаление строки используют конкретный `id` блокировки

Никаких случайных фото: при отсутствии разрешённого URL или ошибке загрузки — UserRound.
Нет нового endpoint общедоступных фото/профилей. После блокировки прежний приватный
`/media/photos/{id}` по-прежнему принадлежит только владельцу. Из списка не обходится
запрет фотографии активного/отклонённого отклика. История D51 остаётся замороженной

Исходный план блокировки без общего отклика/мэтча ранее не сохранялся. Связь с любым
другим планом того же автора не выдумывается: context=null, различение — по коду и дате.
Миграция не нужна; head **0008**, прежние 33 таблицы и все записи сохранены

Разблокировка требует подтверждения. После успешного прежнего DELETE `/me/blocks/{id}`
строка убирается локально; при ошибке остаётся на месте с понятным сообщением. Ни новые
согласия, ни отклики/мэтчи, ни подавленные уведомления не создаются заново

## Уведомления и admin

Строка уведомлений открывает `https://t.me/<VITE_TELEGRAM_BOT_USERNAME>?start=notifications`.
BotHandler распознаёт только доверенное private `/start notifications` и открывает тот же
`notification_settings` с существующими notify:on/off. Согласие не сбрасывается,
настройки не дублируются в Mini App; новых таблиц/API предпочтений/локального переключателя нет

Использован штатный [Telegram deep linking](https://core.telegram.org/bots/features#deep-linking),
проверенный 25.11.2026. Если клиент показывает «Запустить», пользователь подтверждает
переход в боте. Фактическое получение update проверяется отдельно в настоящем Telegram

Ссылка admin появляется только после GET `/admin/session`; при возвращении к видимому
приложению права перепроверяются. Сам `/admin` и каждый его API сохраняют независимые
серверные проверки. Назначение роли через `python -m poidem.admin` не меняется

Удаление использует прежний `deleteAccount`, CSRF/сессию и B13. Диалог остаётся при 409,
показывая причину; успешное удаление переводит на приветствие. Настоящие записи при
автоматизированной проверке не удаляются — только данные изолированной `*_test` и browser fixtures

## Ручная проверка в Telegram

1. На A в анкете изменить имя/описание, выбрать фото и интересы, не сохранять.
   Через шестерёнку открыть настройки, блокировки и вернуться: значения и шаг остаются
2. Открыть уведомления: бот показывает прежнее состояние и inline-переключатель.
   Выключенный opt-out не должен включаться самим переходом. Проверить возвращение WebView
3. В каталоге, анкете, мэтче и чате открыть «…»: карточка и позиция страницы не сдвигаются,
   меню выше навигации, закрывается вне/Escape. Проверить имя в подтверждении и отменить
4. Только на тестовых данных подтвердить блокировку: переписка/мэтч сохраняются,
   новый обмен запрещён. В `/settings/blocked` найти человека по фото/контексту/коду
5. При двух одинаковых именах выбрать нужную строку, сверить код в подтверждении,
   разблокировать: исчезает только она; остальные ограничения и B13 сохраняются
6. A/B без admin не видят ссылку. C с ранее назначенной ролью открывает панель из
   настроек и возвращается обратно; прямые admin API для A/B запрещены
7. Удаление: проверить отмену и B13/409 на аккаунте с общей историей. Успешное удаление —
   только отдельно выбранный тестовый аккаунт без зависимостей, не реальные пользовательские записи
8. Проверить 320/360/390/430 px и desktop, длинные имена, системные safe areas,
   отсутствие «Очистить данные» и закрытие/повторное открытие Telegram

Полное закрытие/перезапуск WebView уничтожает несохранённый черновик в памяти; это
не серверная потеря сохранённой анкеты. Не хранить реальные фото/черновики в localStorage ради обхода
