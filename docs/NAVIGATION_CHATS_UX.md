# Навигация, чаты и «Мои планы» — D60

Подтверждено заданием пользователя: пять разделов «Главная», «Найти», «Мои планы», «Вдохновение», «Чаты». Один плавающий плюс открывает прежний `/create`, находится выше измеренной нижней навигации с учётом safe area и доступен только на пяти основных маршрутах. Вложенные экраны и модальные окна не получают дополнительную кнопку. Палитра, PNG, шрифты, правила знакомств сохранены.

Высота панели измеряется до первого paint, при resize и обновлении корневых CSS-отступов Telegram. Значение округляется вверх до целого CSS px: это исключает недостающий отступ на первом кадре и повторные записи из-за сериализации дробных значений в WebKit. Запись выполняется только при изменении; оба наблюдателя отключаются при выходе.

## Диалоги

`/chats` использует существующие Match, ChatThread, ChatMessage и ChatReadState. Новых таблиц, миграций, чат-сервисов или фоновых механизмов нет. `GET /api/v1/me/chats?cursor=…&limit=20` выдаёт только собственные мэтчи с прежним защищённым MatchDTO, последним сообщением (text/sender/created_at) и last_activity_at. Пустой диалог участвует в списке с датой создания мэтча; остальные — с датой последнего сообщения. Общая сортировка выполняется в PostgreSQL, activity DESC / match_id DESC, курсор привязан к аккаунту. Предпросмотр — обычный текст, не HTML, не передаётся боту/в лог.

Фотография — только прежний защищённый URL анкеты в контексте мэтча. При недоступности — нейтральный силуэт. Основная строка открывает `/match/{id}/chat`, «О встрече» — прежние подробности мэтча, опрос и разрешённый Telegram-контакт. Отсутствие username не мешает переписке. Архивирование и индивидуальное скрытие карточки не удаляют диалог; блокировка по-прежнему запрещает отправку, сохраняя доступную участнику историю.

## Собственные планы

Видимые разделы: «Мои идеи», «Отклики», «Архив». «Выбранные» были исходящими откликами, отдельного избранного не существовало; новая система избранного не добавляется. Входящие доступны из собственного плана и по прежним ссылкам бота `tab=incoming&plan=…`. Старый `tab=matches` ведёт в `/chats`, неизвестный/старый `all` — в идеи. API прежнего общего списка сохранён для совместимости.

`GET /api/v1/me/activity?view=own&scope=active` выбирает только планы автора и сортирует до пагинации:

1. Будущие опубликованные планы с откликами, требующими решения, по ближайшей встрече
2. Остальные доступные будущие опубликованные — по ближайшей встрече
3. Черновики — по последнему изменению
4. Закрытые/прошедшие и прочая неактивная история — по последнему значимому событию, новые первыми

В DTO добавлены только поля представления: pending_response_count, match_id, history. Последние записи показаны в сворачиваемой «Истории» без нового статуса БД. Отменённые и достигшие срока D50 записи остаются в прежнем архиве. Доступ к подробностям подтверждённой встречи сохранён; отдельного списка чатов в планах нет. В «Откликах» сохраняются активные ожидания первыми и компактная история D52, принятые не дублируются.

Выбранный раздел/фильтр хранится в URL и состоянии перехода React Router; возврат из анкеты/мэтча и через Telegram BackButton восстанавливает разрешённый внутренний маршрут. Это не хранилище настоящих анкет или сообщений.

## Общие индикаторы

`GET /api/v1/me/navigation` возвращает pending_responses, unread_messages, unread_dialogs. Первое число учитывает только доступные ожидания будущих опубликованных планов автора, включая блокировки и модерацию. Непрочитанные — реальные чужие сообщения после собственного ChatReadState; свои отправленные сообщения не увеличивают число. Счётчики охватывают все страницы. Нули/недоступные данные не подменяются произвольными значками.

Списки и индикаторы обновляются при открытии, возвращении фокуса/видимости и раз в 30 секунд только на видимой странице. Переход во входящие/исходящие сразу запрашивает отклики, не ждёт следующего интервала. Мутации и прочтение чата запрашивают свежий снимок; уже начатый до мутации запрос не считается окончательным. Существующий polling открытого чата 3 секунды не меняется. Авторизация/эпоха аккаунта проверяются до применения ответа, приватные списки не используются как localStorage fallback.

Ручная проверка A/B: A публикует будущий план, B откликается; у A индикатор и приоритет идеи. A принимает — один диалог появляется у обоих. B пишет, A видит непрочитанное в навигации и строке; открытие чата убирает число. «О встрече» открывает прежний опрос и Telegram-контакт при username. Проверить черновик, закрытый план в истории, архив и скрытие; закрытие чата/возврат восстанавливает вкладку. Не сбрасывать квоты/блокировки ради проверки.
