# Отклики и история в архиве — D52

25.11.2026. Локальное улучшение существующего этапа 5, без изменения архитектуры,
фильтра, палитры, фотографий, шрифтов или маршрутов. Последнее задание пользователя

## Поведение

- В «Полученных»/«Выбранных» активные ожидания первыми, новые выше
- Отклонённые, истёкшие, закрытые выбором другой пары и недоступные ожидания — ниже
  в компактной сворачиваемой «Истории». Если активных нет, она раскрыта при входе
- Сводка свёрнутой истории показывает результат и название плана; при наличии
  отказа он вынесен в сводку. Внутри строки упорядочены по времени результата
- Отказ различает автора («Вы отклонили отклик») и кандидата («Ваш отклик не принят»).
  Повторный отклик не предлагается, ссылок на скрытый план/живую анкету нет
- Историческая строка содержит исход, название, второго участника и дату отклика.
  Используется замороженный history_context; legacy-пометка сохранена
- Принятые пары не повторяются среди откликов: для них «Мэтчи», «Все» и архив,
  с прежними действиями «Написать»/«Подробнее»
- После starts_at только ожидание отображается как «Время плана прошло»;
  принятие и отказ не предлагаются. Accepted/rejected/closed не переименовываются
- Автор раскрывает «Историю откликов» прямо в архивном плане или мэтче и на странице
  архивного мэтча. Список загружается по раскрытию, следующие страницы — по запросу
- В архивной истории: кандидат, дата отклика и результат «Принят», «Отклонён»,
  «Выбрана другая пара» или «Время плана прошло». Решений/ссылок на анкету нет
- Кандидат по-прежнему видит только собственный отклик/мэтч. Ошибка чтения истории
  локальна, есть повтор загрузки, карточка/навигация не пересоздаются

Архивирование — сразу при отмене или через 7 календарных дней в IANA-зоне плана.
Отдельного переноса через 7 дней после отказа нет. История не удаляется, TTL/90 дней
не добавлены. Скрытие персональное; чат, лимиты, окончательный отказ и B13 сохраняются

## API и хранение

Новых endpoints, таблиц, статусов БД или Alembic-миграций нет. Head остаётся 0006

ResponseDTO дополнен:

| Поле | Смысл |
| --- | --- |
| status | Прежний сохранённый статус отклика |
| display_status | Представление: waiting/accepted/rejected/closed/expired/cancelled/unavailable |
| decided_at | Nullable время принятого решения; не заполняется от истечения |

Для status != waiting display_status равен status. Для waiting отмена плана даёт
cancelled; starts_at <= серверному now даёт expired; непубличный/недоступный план
даёт unavailable; иначе waiting. Истечение не является отказом или доказательством
встречи. Прежние проверки принятия/отказа после времени плана остаются на backend

GET /api/v1/plans/{id}/responses?limit=20&cursor=... — существующий endpoint автора,
теперь подключён к архивному UI. Он возвращает все результаты, с next_cursor;
авторизация и право автора проверяются на сервере. Не автор — 404, без входа — 401

GET /api/v1/me/responses?direction=incoming|outgoing продолжает выдавать историю.
UI делит её на активные/исторические и не выдаёт accepted повторно в этих вкладках.
GET /api/v1/me/activity в активном scope исключает истёкшие outgoing; архивный scope
и персональные скрытия не меняются. Доступ к фото/снимкам не расширен

## Проверка двумя аккаунтами

Использовать существующий временный стенд и настоящие тестовые аккаунты A/B
(PowerShell: [CHAT_ARCHIVE_STAGE5](CHAT_ARCHIVE_STAGE5.md#windows-powershell-запуск)).
Не менять время реальной БД для ускорения проверки

1. A публикует будущий план; B откликается. A видит активный входящий первым,
   B — активный исходящий. A отклоняет: у обоих сразу виден результат по своей роли
2. В истории A видит имя/возраст B и название; B видит название и автора,
   без ссылки на недоступный план. При наличии другого активного отклика история
   сворачивается, а отказ остаётся понятен из сводки
3. На другом плане A принимает B: пара есть в «Мэтчах»/«Все», в полученных/выбранных
   не дублируется; прежние чат/подробности работают
4. На плане с близким будущим временем оставить отклик без решения. После starts_at
   обновить: «Время плана прошло», нет принятия/отказа, это не rejected
5. У уже архивного плана A раскрывает «Историю откликов», проверяет имена/даты/исходы
   и пагинацию. B видит собственную запись или мэтч, историю других кандидатов не видит
6. Скрыть/восстановить архивную карточку на A: карточка B и переписка сохраняются
7. Проверить узкий экран, длинные названия, раскрытие/сворачивание и нижнюю навигацию

Новые исправления не объявляются вручную проверенными в Telegram без подтверждения
пользователя. Синтетика и сдвиг часов допустимы только в автоматизированных тестах
