## Сообщения и кнопки

Общий формат: короткий жирный заголовок, пустая строка и максимум две строки
объяснения. Стандартный Telegram HTML, только разрешённая нами разметка; динамические
названия/имена экранируются. Превью ссылок отключены, изображений и баннеров нет.
Системные цвета/шрифты Telegram не меняются

В каждом событийном уведомлении одна кнопка. У /start основная — открытие Mini App,
вторая строка — доступ к уведомлениям. В настройках основная — Включить/Выключить,
вторая — вернуться в Mini App. Заполненная анкета ведёт сразу на /home,
незаполненная — на /profile. Бот не создаёт анкету и не подменяет авторизацию

## Управление уведомлениями

- notify:settings показывает актуальное состояние в том же сообщении
- notify:on/off устанавливают явное значение, а не инвертируют флаг при каждом клике
- Каждый callback проверяет private sender/chat и то, что сообщение отправлено этим ботом
- Состояние сохраняется прежним BotBinding, Username не нужен
- Повторный update не делает повторный edit; повторная явная команда состояния безопасна
- Переключение вызывает editMessageText, без нового sendMessage и без fallback-сообщения
- Ответ callback снимает индикатор нажатия. «Message is not modified» — успешный повтор
- Сетевые ошибки/429 повторяются существующим polling; намерение сохраняет то же значение
- При недоступном для редактирования сообщении — краткий callback alert, настройки
  не откатываются, новые сообщения не создаются. 403 сохраняет прежнюю обработку denied

/notifications_on и /notifications_off по-прежнему принимаются для совместимости,
но не рекламируются в текстах или меню. /notifications открывает компактные настройки.
Меню содержит только вход в приложение и управление уведомлениями

## Контекст и приватность

Названия/имена в откликах берутся из разрешённого history_context; для received/accepted
при необходимости доступно разрешённое название плана. Rejected/closed не используют
живую анкету или закрытое название вместо отсутствующего снимка. Контакты, Telegram ID,
username, фотографии и тексты переписки в уведомления не добавлялись. Чат называет
свой план только после прежних проверок Match/участника/модерации

Все переменные вставляются как экранированный текст, пользовательский HTML не работает.
Тексты/нажатия/секреты в логи не попадают. Отказ по-прежнему окончательный;
closed не превращается в отказ автора

## Прямые переходы

- /plans?tab=incoming&plan=UUID — входящие указанного плана
- /plans?tab=outgoing&plan=UUID — собственный ответ, история раскрыта без лишнего клика
- /plans?tab=archive&plan=UUID — архивная история указанного плана
- Мэтч/чат используют существующие /match/UUID и /match/UUID/chat

В MyPlans только расширена поддержка plan-параметра. Для архива прежний защищённый
GET /api/v1/me/activity получил необязательный plan_id. Фильтр применяется на сервере
до пагинации поверх прежних проверок роли/личного скрытия, а не к одной случайной странице.
Cursor привязан также к plan_id; старые cursor без фильтра совместимы. Чужой план
не открывается по ссылке; скрытая карточка не восстанавливается автоматически.
Клик обычной вкладки снимает адресный фильтр, обновление текущего архива не делает remount.
Новых экранов, маршрутов, styles, фотографий или шрифтов нет

Coalescing чата D53 не изменялся: один открытый пакет, 20 секунд тишины/предел 60,
серверная прочитанность/notified_through, частотный предел, существующие notification_jobs
